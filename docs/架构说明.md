## 1. 系统是什么

一个「对话为入口、工具为手脚、沙箱为工作台、权限为围栏」的智能体平台。三句话概括：

1. **模型不是主体，工具才是能力的来源**。模型只能调用被装配进它上下文的工具；
   没权限的工具**不进清单**，所以「越权」不是被拒绝，而是物理上不存在。
2. **执行发生在沙箱里，宿主只负责编排**。读写文件、跑 Python、生成报表都在
   每个用户独立的 OpenShell 容器里；宿主进程不执行用户代码。
3. **状态分三处存**：业务数据（MySQL）、对话图状态（PostgreSQL checkpointer）、
   缓存与限流（Redis）。三者职责不重叠。

## 2. 设计原则（以及它们换来了什么）

| 原则 | 具体做法 | 换来了什么 / 代价 |
|---|---|---|
| **能力按角色装配** | 工具清单在创建 agent 时按 `pa_roles.tools` 解析，未授权的工具不进 `tools=[...]` | 越权在提示词层面不可见；代价是换角色要重建 agent（见 §6.1 的 epoch 机制） |
| **执行与编排分离** | 工具在沙箱内跑，宿主只拼命令行并转发 | 宿主不需要 `sudo`、不需要装 pandas；代价是跨进程 IO（每次 exec 5~50ms） |
| **每用户一个沙箱** | `agent-<username>` 命名，文件天然隔离 | 隔离彻底；代价是首次对话要等容器创建（5~10s，见 §7.2） |
| **失败不阻断主流程** | 除 PG checkpointer 外，所有可选组件（沙箱/KB/MCP/Redis）失败只降级 | 单点故障不会让平台全挂；代价是"静默降级"需要日志兜底（§17） |
| **状态与进程解耦** | 对话状态落 PG，业务数据落 MySQL，进程无本地状态（除 LRU 缓存） | 可以多 worker、可重启；代价是每次读会话都要查库 |
| **配置与密钥分离** | `configs.cfg` 只放非敏感项，密钥一律环境变量 `PA_*` | 配置可进仓库；代价是部署时变量多（§13） |

## 3. 运行时拓扑

### 3.1 进程与端口

```
┌─────────────────────────────── 虚拟机 / 单机 ───────────────────────────────┐
│                                                                             │
│  uvicorn × N workers (5001)        嵌入服务 (5110)       OpenShell gateway  │
│  ├─ FastAPI 路由/SSE               ├─ fastembed ONNX      (127.0.0.1:17670)  │
│  ├─ AgentManager (LRU 128)         └─ 768 维向量          └─ Docker 引擎     │
│  └─ 工具调用 ─────────────────────────────┐                   │             │
│                                            │                   │             │
│  MySQL (3306)      PostgreSQL (5432)       │         沙箱容器 agent-<user>    │
│  业务表             checkpointer           └────────► (pa-sandbox:1.3)       │
│  Redis (6379)      kb 库 (pgvector)                   每用户一个            │
│  缓存/限流                                                                   │
└─────────────────────────────────────────────────────────────────────────────┘
        ▲                                        ▲
        │ 浏览器（Vue SPA，同源 5001）            │ 定时器：日志/产物/沙箱回收
```

| 进程 | 端口 | 职责 | 挂了会怎样 |
|---|---|---|---|
| `open-agent-harness`（uvicorn） | 5001 | Web、SSE、agent 编排 | 全站不可用 |
| `pa-kb-embed` | 5110（仅回环） | 嵌入/重排推理 | 知识库检索失败，对话不受影响 |
| OpenShell gateway | 17670（仅回环） | 沙箱生命周期 | 沙箱类工具报错，对话仍可用 |
| MySQL | 3306 | 业务数据 | 服务能启动，但登录/会话/权限全部报错 |
| PostgreSQL | 5432 | 对话图状态 | **启动即退出**（唯一阻断启动的依赖，见 §9.2） |
| Redis | 6379 | 权限缓存、限流、去重 | 降级为查库 + 限流失效，功能仍可用 |

### 3.2 并发模型

- **worker 是进程**，不是线程：`uvicorn --workers N`，每个进程独立解释器、独立 GIL。
  内存按 `N × (250~400MB)` 计（含 langgraph 依赖）。
- **线程**只出现在两处：worker 内的 anyio 线程池（跑同步 `def` 端点、文件 IO，默认 40 个）、
  以及沙箱管理器的按名互斥锁（§7.2）。
- **SSE 连接不占线程**：对话链路全 `async def`，一个 worker 可以挂几百条流式连接，
  真正的瓶颈是模型 API 的并发与延迟。
- 经验值：`workers ≈ min(CPU 核数, 内存GB / 2)`。4 核 6G 的机器取 3。

## 5. 一次对话的完整生命周期

这是全系统最长的链路，其他功能都是它的旁支。

### 5.1 时序

```
浏览器                FastAPI                 chat/stream          AgentManager        沙箱/PG/MySQL
  │  POST /api/chat       │                        │                    │                  │
  ├──────────────────────►│ require_login          │                    │                  │
  │                       ├───────────────────────►│ ① 确保会话存在     │                  │
  │                       │                        ├────────────────────┼─────────────────►│ MySQL
  │                       │                        │ ② 落用户消息       │                  │
  │                       │                        ├────────────────────┼─────────────────►│ MySQL
  │                       │                        │ ③ 取/建 agent      │                  │
  │                       │                        ├───────────────────►│ LRU 命中?        │
  │                       │                        │                    ├─ 未命中：装配工具 ─► MySQL(RBAC)
  │                       │                        │                    ├─ 建沙箱后端 ─────► OpenShell
  │                       │ ④ SSE 逐块返回          │                    │                  │
  │◄══════════════════════┤◄───────────────────────┤ agent.astream      │                  │
  │  content/reasoning/   │                        │ 工具调用 ──────────┼─────────────────►│ 沙箱 exec
  │  step/options/done    │                        │ 每步写轨迹 ────────┼─────────────────►│ pa_trace_log
  │                       │                        │                    │                  │
  │                       │                        │ ⑤ 检查 interrupt   │                  │
  │                       │                        ├────────────────────┼─────────────────►│ PG checkpoint
  │                       │                        │ ⑥ 后台收尾          │                  │
  │                       │                        └────────────────────┼─────────────────►│ 摘要/产物/缓存
```

### 5.2 各步细节

**① 会话与消息（MySQL）**
`stream.py` 先 `SessionDao.ensure(session_id, username)`，再落用户消息。会话表
`chat_sessions` 用 `(session_id, username)` 唯一，`chat_messages.session_id` 存的是
**主键 id** 而不是前端会话号（历史包袱，DAO 里做了转换）。

**② agent 装配** 见 §6.1，这一步最贵（要查 RBAC、建沙箱后端、编译图），所以有 LRU 缓存。

**③ 流式执行**：`agent.astream(..., stream_mode="messages")`，逐 chunk 解析：
- `AIMessageChunk.content` → `{"content": "..."}`
- `additional_kwargs.reasoning_content` → `{"reasoning": "..."}`（**也推给前端**，
  同时保留在 state 里维持多轮推理链）
- `ToolMessage` → 解析出工具名/参数/结果，先推 `{"step": {...status:"running"}}`，
  完成后推 `{"step": {...status:"done", elapsed, detail}}`，并写一条轨迹

**④ SSE 事件协议**（前端按字段名分发，全量只有这些）：

| 字段 | 载荷 | 含义 |
|---|---|---|
| `content` | 字符串 | 正文增量 |
| `reasoning` | 字符串 | 思考增量（可折叠展示） |
| `step` | `{id,name,label,status,elapsed?,detail?}` | 工具调用的过程卡片 |
| `options` | `{question, options:[...]}` | `ask_user` 中断，等待用户点选 |
| `url` | `{url, name?}` | 让前端打开某个页面（导航事件） |
| `reset` | `true` | 丢弃当前已渲染内容（重试/回滚） |
| `typing` | `false` | 先解锁输入框（收尾还没完成） |
| `done` | `true` + `session_id` | 本轮结束，前端刷新会话列表 |
| `error` | 字符串 | 出错，同时仍会补一条 `done` |

**⑤ 中断与恢复**：`ask_user` 工具内部调用 LangGraph 的 `interrupt()`，图停在
checkpoint 上。后端从 `aget_state()` 里找 pending interrupt，推 `options` 事件后
**正常结束本轮 SSE**。用户点选后前端发第二次请求，带 `resume_value`，后端用
`Command(resume=value)` 从断点继续——这也意味着**刷新页面/换设备都能接着选**。

**⑥ 后台收尾**：`_spawn_post_turn` 挂成 asyncio task（不是线程，因为 PG 连接池
绑定事件循环）：上下文治理（压缩/摘要）、技能工具缓存失效、指标落盘。收尾失败
只记日志，不影响已经给用户的回答。

### 5.3 上下文治理

预算 `[agent] context_char_budget`（默认 24000 字符，`Configs` 兜底 60000）。
顺序是**先便宜后昂贵**：

1. 压缩工具输出（保留首尾、中间省略）；
2. 滚动摘要：把更早的轮次压成一段摘要写进 `chat_sessions.summary`，
   并从 state 里移除原文；
3. 最后才丢最老的消息。

单轮还有两个硬约束：`turn_max_seconds`（默认 900）与 `turn_max_steps`（默认 40），
超时/超步数直接终止并给出提示，避免模型在工具循环里空转烧钱。

## 6. 智能体内核

### 6.1 AgentManager 与缓存

`AgentManager`（`agent/main_agent.py`）是进程级单例，持有三项状态：

| 状态 | 结构 | 键 | 淘汰 |
|---|---|---|---|
| agent 缓存 | `OrderedDict`，上限 **128** | `<session_id>_<username>` | LRU |
| 模型客户端 | `ChatOpenAIWithReasoning` | — | 进程内复用，`streaming=True, temperature=0, timeout=120s` |
| epoch | 字符串 + 检查时间戳 | — | 每 30s 比对一次，变了就全量清缓存 |

**epoch 解决什么问题**：工具授权、技能包、MCP 配置都是"装配期"决定的，改完如果不
重建 agent，模型还在用旧清单。所以把「权限/工具元数据/技能」的版本号拼成 epoch 字符串，
定时比对，一变就让缓存整体失效——比在每个写接口里手工清缓存可靠。

**沙箱后端是条件注入的**：`build_backend(username)` 返回 `None` 时（未启用/不可用），
不传 `backend=` 参数，deepagents 的内置文件工具退化为默认行为。这一步失败只告警，
**不允许**让 agent 创建失败。

### 6.2 中间件链

顺序即执行顺序（后者包前者）：

| 顺序 | 中间件 | 职责 | 为什么需要 |
|---|---|---|---|
| 1 | `FixToolNameMiddleware` | 修正模型编造的工具名（模糊匹配到真实工具）；检测同一工具反复失败的幻觉循环 | 模型偶发把 `kb_search` 写成 `kb_search_tool`，直接报错会让用户看到"工具不存在" |
| 2 | `ToolOutputGuardMiddleware` | 截断/标记超长工具输出 | 一次 `cat` 大文件就能把上下文撑爆 |
| 3 | `HostMemoryMiddleware` | 从**宿主仓库**读 `AGENT.md` 注入系统提示 | deepagents 的 memory 参数按**沙箱路径**读文件，沙箱里没有 `AGENT.md`，以前每次白跑一次 exec |
| 4 | `PermissionHintMiddleware` | 把"你缺哪些写操作"提前告诉模型 | 否则模型先问一堆参数，最后才说"我没有这个接口" |
| 5 | `SkillsMiddleware`（deepagents，条件） | 读 `/sandbox/skills/**/SKILL.md` 注入技能说明 | 技能包是用户私有能力，必须按用户隔离 |

> 注意顺序：工具名修正必须在最外层，否则后续中间件拿到的是错误工具名。

### 6.3 工具装配（四层，逐层过滤）

```
registry.REGISTRY（代码声明的 7 个内置工具）
   │  ① resolve_tools(username)：按角色 pa_roles.tools 过滤；管理员 `*` 全给
   ▼
内置工具（ask_user / sandbox_shell / 记忆 4 件套 / kb_search）
   │  ② ALWAYS_ON_NAMES：6 个人人可用（kb_search 不在其中，需授权）
   │
   ├─ 技能自带工具（load_skill_tools）——**不参与 RBAC**，因为技能是用户自己的
   │     · skill_tools_lazy=true 时只注册"本会话读过 SKILL.md"的技能
   │
   └─ MCP 工具（mcp_manager.load_tools）——先按 pa_tools.always_on 或角色过滤
```

工具元数据（显示名/分组/风险/是否停用/是否人人可用）存在 `pa_tools`，**代码决定
"有没有这个能力"，数据库决定"怎么展示、给不给"**。两者不一致时以代码为准。

运行时工具清单（`GET /api/tools`）会把 `visible/ghost/enabled` 一并返回，
前端据此决定「工具管理」页显示什么。

### 6.4 子代理

`[agent] enable_subagent=false`（默认）时注册一个**禁用占位**子代理，防止模型
幻觉出 `task` 工具；打开后才放开 deepagents 的 `general-purpose`。默认关的理由：
单场景查询用不到，放开只会多烧 token、多一层不可控链路。

## 7. 沙箱子系统（OpenShell）

### 7.1 为什么是独立运行时

宿主进程不执行用户代码。沙箱内是 **非 root + `/usr` 只读 + 无 sudo**，所以：
apt 装不了东西、pip 只能装纯 Python 包 —— 系统级能力必须预装进镜像
（`docker/pa-sandbox.Dockerfile`，含中文字体、pandoc、Chromium、Node/JDK/Go/Rust
与 4 个转换命令 `html2pdf/docx2pdf/xlsx2pdf/html2png`）。

### 7.2 生命周期状态机

```
（不存在）──create──► Ready ──闲置 7 天──► Stopped ──start──► Ready
                        │                     
                        └──Error──start 失败──► destroy + create（**丢文件**，会 WARNING）
```

- **创建**：`openshell sandbox create --name agent-<user> --policy <策略> --from <镜像>`
  `--cpu/--memory`，超时 300s。
- **按名加锁**：`_lock_for(name)`，不同用户并发建、同名串行。用一把全局锁会让
  「20 个新用户同时上线」变成串行 40 秒。
- **恢复优先于重建**：服务重启后不删沙箱，遇到 `Stopped` 先 `start`，文件全保留。
- **删除只在两种情形**：用户明确要求清空；或沙箱 `Error` 且 `start` 恢复失败。

### 7.3 策略

`config/sandbox-policy.yaml`，核心理念 **deny-by-default**：

- 文件系统：Landlock 白名单，只放 `/sandbox`（`read_write`）与少量只读路径；
  未列出的路径连 `ls` 都不行；
- 网络：默认全拒，按规则放行；
- `/dev/null` 必须可写 —— 否则 deepagents 内置文件工具拼出的 `2>/dev/null`
  会让整条命令 rc=1 且零输出，模型误判"文件不存在"（踩过的坑）；
- 策略在**创建时锁定**，改了要重建沙箱；网络规则可热改。

### 7.4 产物回收

沙箱内 `/sandbox/output/` 的文件，在轮次结束时由 `collect_artifacts()`
上传到宿主 `artifacts/<用户名>/<会话号>/`，再通过 `GET /api/artifacts/...`
下载。**安全边界**：只在自己用户名目录下找，路径穿越被挡。

保留策略：`pa-artifacts.timer` 每天清理 90 天未访问的产物目录。

### 7.5 技能包

技能 = 沙箱里的一个目录：`/sandbox/skills/<name>/SKILL.md`（说明）+ 可选
`tools.json`（声明的工具）。两条注入路径：

1. `SkillsMiddleware` 读 `SKILL.md` 进系统提示（告诉模型"你会什么"）；
2. `SkillToolsService` 把 `tools.json` 里声明的命令包装成工具（告诉模型"能调什么"）。

技能工具**不参与 RBAC**：技能在用户自己的沙箱里，天然按用户隔离，角色只管
内置工具与 MCP 工具。`skill_tools_lazy=true` 时按需披露，技能多了可省一大截提示词。

## 8. 知识与记忆：三层不要混

| 层 | 存哪 | 写入方式 | 检索方式 | 适合放什么 |
|---|---|---|---|---|
| **偏好** | MySQL `pa_user_prefs` | 模型调 `remember_preference`，或用户在设置页改 | 每轮注入（有预算上限） | 称呼、格式、语气 |
| **业务知识（事实）** | MySQL `pa_knowledge` | 模型调 `remember_fact`（带来源/时间） | 关键词召回 + 注入 | "我们公司的口径是…" |
| **文档资料** | PostgreSQL `kb` 库（pgvector，LlamaIndex 管理） | 用户上传文件 → 异步索引 | 向量 + 关键词混合召回 | 制度、手册、合同、报告 |

前两层是**结构化短文本**，规模小、每轮全量注入；第三层是**非结构化长文档**，
必须检索。混用会同时污染上下文和检索质量，详见 [`知识分层说明.md`](知识分层说明.md)。

### 8.1 知识库链路

```
上传 → kb_doc(sha256 去重) → kb_task(pending)
     → kick() 起后台 worker → LlamaIndex readers(页码/小节) → SentenceSplitter(中文按字符切)
     → LocalEmbedding(HTTP 调 5110) → PGVectorStore(data_kb_nodes：正文 + 向量 + metadata_)
检索 → VectorIndexRetriever(filters=scope) ‖ KeywordRetriever(pg_trgm)
     → QueryFusionRetriever(RRF, k=60) 取 20 → 本地重排 → 取 top_k
     → build_context(默认 2500 字符预算) → 交给模型
```

设计要点：

- **必须混合**：纯向量对数字/专有名词不敏感，纯关键词对同义改写不敏感；
  RRF 只用排名不用分值，避免两种分数量纲打架。
- **权限下推**：`scope=global ∪ (scope=user ∧ owner=本人)` 作为 metadata filter / SQL 条件，
  不是召回后再筛 —— 否则越权片段已经进了模型上下文。
- **嵌入服务独立进程**：塞进 uvicorn 的 N 个 worker 会各加载一份模型，内存翻 N 倍。
- **重排默认关**：CPU 上两个模型同进程会把单条嵌入从 0.3s 拖到 8s，而重排超时只有 200ms。
- **扫描件 OCR**：无文字层的 PDF 逐页渲染（DPI 150，最多 30 页）交给视觉模型；
  走 OpenAI 协议的 `/chat/completions`，可指向内网网关，文档不出网。

连接：`mysql+asyncmy`，`pool_size=20, max_overflow=40, recycle=3600`，
连接初始化固定 `SET time_zone='+00:00'`（否则 `func.now()` 与代码里的 UTC 差 8 小时）。

建表：服务启动时 `ensure_tables()` 对 ORM 表 `create_all`（幂等），并用 MySQL 命名锁
`GET_LOCK('pa_schema_init')` 串行化多 worker，避免撞 1050。`pa_*` 表各自
`CREATE TABLE IF NOT EXISTS`，首次使用时自建。

### 9.2 PostgreSQL

| 库 | 表 | 用途 |
|---|---|---|
| `open_agent_harness` | `checkpoints` / `checkpoint_blobs` / `checkpoint_writes` / `checkpoint_migrations` | LangGraph 图状态（每轮消息、待恢复的 interrupt） |
| `kb` | `kb_doc` / `kb_task`（业务状态）/ `kb_nodes` + `data_kb_nodes`（LlamaIndex 建的向量表） | 知识库 |

`open(wait=True, timeout=10)`，`setup()` 建表对 `UniqueViolation` 重试 3 次；
其它错误关池后 **raise**——这是**唯一会让服务启动失败**的依赖，因为
`AsyncPostgresSaver` 没有内存降级实现。

| `rbac:perm:<user>` | 300s | 权限快照（角色+工具集） |

## 10. 鉴权与权限

### 10.1 会话

自带实现的 **Flask 兼容签名 cookie**（`web/session.py`）：cookie 名、序列化格式、
签名算法都与 Flask 的 `itsdangerous` 对齐。这样从 Flask 迁到 FastAPI、或回滚，
都**不需要重新登录**。密钥来自 `PA_APP_SECRET_KEY`，多 worker 必须一致。

### 10.2 权限模型

```
用户 ──(pa_user_roles)──► 角色 ──(pa_roles.tools)──► 工具清单
                                     │
                                     ├─ "*"        → 全部内置工具（管理员）
                                     ├─ "mcp_*"    → 该前缀的 MCP 工具
                                     └─ "工具名"    → 精确匹配
```

- `permissions(username)`：一次 JOIN 拿到角色与工具集，`is_admin` 取 OR；
- `allows_tool()`：`*` / 精确名 / `mcp_*` 通配；
- **安全默认**：异常 → 空工具集（viewer）；无角色 → 只给公共工具；
- `is_last_active_admin()`：禁止停用/删除最后一个管理员，避免把自己锁在门外。

**内置两个角色**（首次建库时播种）：

| 角色 | 工具 | 说明 |
|---|---|---|
| `admin` | `*` | 全部内置工具 + MCP + 角色分配 |
| `default` | 播种时用「公共工具」（`always_on` 集合）填充，之后不覆盖已有配置 | 新用户默认挂它；**`kb_search` 不在公共集合里**，非管理员要用知识库需管理员显式授权 |

### 10.3 缓存两层

Redis 优先（300s），本地 dict 兜底（60s，仅 Redis 不可用时启用）。
**失效是主动的**：`assign/set_role_tools/create_role/delete_role/delete_user`
都会 `invalidate(user)` 或全量清 `rbac:perm:*`，TTL 只是兜底。

### 10.4 登录

表单 POST → 限速（20 次/分钟/IP）→ 账号存在且 `status=active` → 有 `password_hash`
→ `bcrypt` 校验（cost=12）→ 写 session → 302 到目标页。

**防枚举**：账号不存在与密码错误返回同一句提示；未设密码单独提示由管理员重置。

**开放重定向防护**：`_safe_next()` 只允许 `PREFIX/` 开头的站内路径。

## 11. Web 层

### 11.1 中间件顺序（由外到内）

```
RequestContextMiddleware    请求 ID、访问日志、413 拦截
  └ FlaskCompatibleSessionMiddleware   cookie 验签、session 读写
      └ CORSMiddleware                 与 Flask-CORS 默认一致（*）
          └ 业务路由 / 异常处理器
```

异常分三类，响应形态不同：

| 异常 | API 请求 | 页面请求 |
|---|---|---|
| `LoginRequired` | 401 + `login_url` | 302 到登录页 |
| `AccountDisabled` | 403 | 302 到登录页 |
| 未捕获 `Exception` | 500 JSON（不泄露堆栈） | 500 纯文本 |

`error_detail=false` 时，接口错误一律给通用提示，真实异常只进日志。

### 11.2 路由分区

全部挂在 `/open-agent-harness` 前缀下，按职责分 11 个模块（另有登录/探针直接写在 `app_fastapi.py`）：

| 模块 | 代表端点 | 说明 |
|---|---|---|
| `chat` | `POST /api/chat`、`/api/sessions`、`/api/artifacts/...` | 对话、会话、产物、健康检查 |
| `rbac` | `/api/users`、`/api/rbac/roles`、`/api/rbac/catalog` | 用户/角色/授权 |
| `skill` / `platform_skill` | `/api/skills`、`/api/platform-skills` | 个人技能与平台技能 |
| `sandbox` | `/api/warm`、`/api/sandbox/files` | 沙箱预热与文件浏览 |
| `kb` | `/api/kb/docs`、`/api/kb/search` | 知识库 |
| `knowledge` / `prefs` | `/api/knowledge`、`/api/prefs` | 业务事实与偏好 |
| `mcp` | `/api/mcp/servers` | MCP 服务管理 |
| `audit` / `trace` | `/api/audit`、`/api/trace` | 审计与轨迹查询 |
| `-`（app 内） | `/login`、`/api/health`、`/api/version`、`/api/user/currentUser` | 认证与探针 |

静态资源：`/assets/*` 走 `StaticFiles`，文件名带内容哈希 → 长缓存；
`index.html` 加 `no-cache`，保证发版后立即生效。

### 11.3 健康检查

`GET /api/health` 返回 `{"ok":true,"db":"ok","redis":"ok"}`：DB 探活是
`SELECT 1`，Redis 探活失败只标记 `"redis":"degraded"`，**不让健康检查整体失败**。

## 12. 前端

单页 Vue 3 + Vite，**没有 vue-router**。

- **导航**：`openTabs` 数组 + `activeTab`，标签页可开可关（会话固定）；
  系统管理五个页面共用同一个 pane，靠 `sysTab` 切换。URL 只持久化 `?session_id=`。
- **对话流**：`fetch` POST + `ReadableStream` **手工解析 SSE**（按 `\n` 切行、只认
  `data: `），事件类型与 §5.2 一一对应；300 秒无事件自动 abort。
- **中断**：每个会话一个 `AbortController`，停止按钮直接 abort；`resume` 是发一次
  新的 POST（带 `resume_value`），失败回滚已选状态。
- **Markdown**：`marked`（gfm + breaks）→ 给链接补 `target=_blank rel=noopener`
  → `DOMPurify.sanitize` → `v-html`。没有代码高亮库。
- **状态**：无 Pinia/Vuex，`<script setup>` + `ref/computed`；消息按会话号存字典，
  LRU 上限 12 个会话防内存膨胀；会话列表滚动分页。
- **样式**：Element Plus 只注册未实际使用（0 个 `el-*` 组件），界面是手写 div/svg，
  单一全局 `<style>`，无暗色模式。

## 13. 配置体系

三层优先级：**环境变量 > `configs.cfg` > 代码默认值**。

- 文件只放非敏感项（地址、端口、开关、阈值），密钥一律环境变量；
- 变量名规则：`PA_<SECTION>_<KEY>`，全大写，例如 `[db] mysql_pass` →
  `PA_DB_MYSQL_PASS`，`[agent] pg_pass` → **`PA_AGENT_PG_PASS`**（前缀是段名，
  写成 `PA_PG_PASS` 会静默不生效——踩过）；
- 读取用 `cfg.<camelCase>`，`Configs` 是双重检查锁单例，进程内只读一次；
- 改配置要**重启**才生效（除 `.env` 里的安装期标记）。`AGENT.md` 是 agent 创建时
  读一次并缓存，改完也要重启。

安装期标记（`install.sh` 写入 `.env`）：`PA_INSTALL_USE_CONDA`、
`PA_INSTALL_CONDA_PREFIX`、`PA_INSTALL_CONDA_ENV`，用来保证重跑安装脚本时
**不会把环境改回去**。

## 14. 部署拓扑

### 14.1 单元

| 单元 | 类型 | 作用 |
|---|---|---|
| `open-agent-harness.service` | 常驻 | 主服务（uvicorn，`--workers` 由安装脚本决定） |
| `pa-kb-embed.service` | 常驻 | 嵌入服务（独立 conda 环境，`MemoryMax=2G`） |
| `pa-logs.timer` | 每天 03:00 | 日志切分 + 过期清理 |
| `pa-artifacts.timer` | 每天 03:10 | 产物 90 天清理 |
| `pa-sandbox-idle.timer` | 每天 03:20 | 闲置 7 天沙箱停机（保文件） |
| `pa-sandbox-orphan.timer` | 每天 03:30 | 用户已删且超 3 天的沙箱销毁 |

启动顺序由 systemd 的 `After/Wants=network-online.target` 决定，**不保证** MySQL/PG
先就绪——所以 `lifespan` 里要做连通性自检（PG 连不上直接 fail-fast）。

### 14.2 启动时做的事（lifespan）

1. `ensure_tables()`：建 ORM 表 + 统一排序规则（失败只记 ERROR，不阻断）；
2. `init_checkpointer_async()`：PG 连接池 + 建表（**失败即退出**）；
3. 知识库 `ensure_schema()`（启用时，失败只告警）；
4. 管理员密码自检（`admin` 无密码时打 WARNING）；
5. 关闭时只打日志，连接池交给进程退出回收。

### 14.3 端口暴露

默认只有 5001 对外。3306/5432 由 ufw 限制到指定来源，5110/17670 只绑回环。
生产建议把 5001 也收到反向代理后面，并关掉 `PA_APP_TEST_LOGIN_ENABLED`（已废弃）。

## 15. 可观测性

| 维度 | 载体 | 内容 | 谁看 |
|---|---|---|---|
| 应用日志 | `logs/app.log` + journald | 请求 ID、耗时、异常堆栈 | 运维 |
| 轨迹 | `pa_trace_log` + `logs/trace-*.jsonl` | 每步工具调用（参数、结果、耗时、风险） | 用户（会话内"轨迹"页）与管理 |
| 审计 | `pa_audit_log` | 写/执行类操作、参数打码、结果 | 管理员（审计页） |
| 指标 | `logs/turn_metrics.jsonl` + 进程内 ring | 每轮 tokens/步骤/耗时 | `/api/metrics/summary` |

**审计与轨迹刻意分表**：审计是合规视角（"谁改了数据"），保留不随会话删除；
轨迹是调试视角（"模型为什么这么答"），删会话时随之清理。

敏感参数在写审计前会被递归打码（`password/token/secret/api_key/身份证/银行卡`，
深度 ≤6）并截断 500 字；轨迹只做首尾裁剪不做打码（它可能包含业务数据，靠权限控制访问）。

## 16. 扩展点

| 想加什么 | 怎么做 | 注意 |
|---|---|---|
| **一个工具** | `src/plugins/tools/<name>/`：`manifest.json`（名/模块/risk）+ `@tool` 函数 + `__init__.py` | 重启后在「工具管理」看到；要先分配给角色模型才能调 |

## 17. 失败与降级矩阵

| 组件 | 不可用时发生什么 | 用户看到 | 是否阻断启动 |
|---|---|---|---|
| PostgreSQL | checkpointer 建池失败 → `lifespan` 抛异常 | 服务起不来（systemd 反复重启） | **是** |
| MySQL | 建表/权限查询失败 → 日志 ERROR | 登录报错、会话列表空、工具装配退回公共集 | 否 |
| Redis | 权限缓存/限流/去重全部退化 | 功能正常，限流与防重复失效 | 否 |
| 沙箱 / OpenShell | `build_backend()` 返回 None | 没有文件/命令类工具，模型说"我没有这个能力" | 否 |
| 嵌入服务 | `/api/kb/stats` 里 `embed.ok=false` | 检索报错或超时，对话不受影响 | 否 |
| pgvector / kb 库 | `ensure_schema` 失败 | `/api/kb/*` 报错 | 否 |
| 模型 API | 调用失败/超时 | 对话报"本轮处理出了点问题" | 否 |
| MCP 服务 | 启动加载失败 | 该批工具消失，其余正常 | 否 |
| 磁盘满 | 日志写失败、产物回收失败 | 写入类操作报错 | 否（但很快恶化） |

统一原则：**只有对话状态（PG）值得 fail-fast**，其余一律降级 + 日志。

## 18. 容量与性能特征

| 维度 | 量级 | 说明 |
|---|---|---|
| 单 worker 内存 | 250~400 MB | 主要是 langgraph/deepagents 的 import 与缓存 |
| agent 缓存 | 128 个实例 | 每个实例持有编译后的图 + 工具清单；会话多了会占内存 |
| 单会话首轮 | 3~15 秒 | 沙箱创建 5~10s 是主要开销，之后走缓存 |
| 工具调用往返 | 5~50 ms | 本地 CLI + 容器 exec |
| 嵌入单条 | 0.3 秒（CPU，4 线程） | 开重排会掉到 8 秒，所以默认关 |
| 检索 | 50~200 ms | 向量 + 关键词 + RRF |
| SSE 并发 | 单 worker 数百条 | 瓶颈在模型 API，不在进程 |
| 沙箱密度 | 1 用户 1 容器，约 0.5~1 GB | 闲置 7 天停机，重启即恢复文件 |

扩容优先级：加内存 > 加 worker > 加机器（多机需要共享 PG/MySQL/Redis 与共享沙箱网关）。

## 19. 已知边界与技术债

1. **PG 是硬依赖**：文档曾写"可选/自动退化为内存"，异步化后没有内存实现，
   连不上即启动失败。要么补 `InMemorySaver` 降级，要么保持现状并在文档强调（已改文档）。
2. **前端是单文件巨石**：`App.vue` 约 5200 行，五个系统页面共用一个 pane，
   改一处容易碰坏另一处；且注册了 Element Plus 却没用。
3. **`chat_messages.session_id` 存的是主键**而非前端会话号，属历史设计，
   DAO 里做了隐式转换，新增查询容易踩。
4. **沙箱策略改动要重建沙箱**（文件系统部分创建时锁定），运维上要知道这一点。
5. **`openshell doctor check` 是误报**（snap 严格沙箱看不到宿主 docker），
   会误导排障；已在文档标注。
6. **登录只有一个口令模型**：账号密码 + 全局限速，没有 MFA、没有 SSO 接口。
7. **`AGENT.md` 与 agent 缓存**：改完必须重启，否则旧提示词继续生效。
8. **无并发写入冲突处理**：同一会话两个浏览器同时发消息，后写的覆盖先写的
   （有 Redis 去重，但不解决并发语义）。
