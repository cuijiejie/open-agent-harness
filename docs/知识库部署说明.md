# 知识库（文档 RAG）部署说明

主系统跑起来之后**可选**加的一块：让智能体能检索上传的 PDF / Word / Excel / PPT。
走的是「LlamaIndex + pgvector + 本地嵌入模型 + 混合检索（向量 + 关键词）」，**文档不出内网**。

整体只有三个进程：

```
主服务（uvicorn）──HTTP──> 嵌入服务（127.0.0.1:5110，独立进程，只占一份模型内存）
      │
      ├── PostgreSQL（kb 库 + pgvector 扩展；向量表由 LlamaIndex 维护）
      └── 索引 worker（解析→切分→嵌入→写向量库，上传后立刻触发）
```

> 嵌入模型**必须独立进程**。塞进 uvicorn 的 4 个 worker 里会各加载一份模型，内存直接翻 4 倍。

---

## 1. 装 pgvector

**优先用发行版包**，别源码编译：

```bash
sudo apt install -y postgresql-16-pgvector      # PostgreSQL 16；14/15 换版本号
apt-cache policy postgresql-16-pgvector         # 先确认源里有（Ubuntu 24.04: 0.6.0）
```

> ⚠️ **源码编译在本机实测会崩**：pgvector 0.7.4 + PG 16.15 aarch64 能 `make install`
> 成功、`vector.so` 也在，但 `CREATE EXTENSION vector` 直接段错误
> （`server process terminated by signal 11`，实例自动恢复）。换成
> `postgresql-16-pgvector`（0.6.0）后一次成功。
>
> 编译过的话先清干净再装包，避免混用：
>
> ```bash
> sudo rm -f /usr/lib/postgresql/16/lib/vector.so*
> sudo rm -rf /usr/share/postgresql/16/extension/vector*
> ```

## 2. 建 kb 库

```bash
sudo -u postgres psql -c "CREATE DATABASE kb;"
sudo -u postgres psql -d kb -c "CREATE EXTENSION IF NOT EXISTS vector;" \
                      -c "CREATE EXTENSION IF NOT EXISTS pg_trgm;"
```

表不用手动建，第一次索引/访问时自动建：

- 业务状态：`kb_doc`（文档登记/状态机）、`kb_task`（索引任务队列）
- 向量与正文：`data_kb_nodes`（LlamaIndex 的 PGVectorStore 自己维护，
  含 HNSW 索引 `vector_cosine_ops`）

## 2.1 从旧版（自研 RAG）升级

旧版用过 `kb_chunk` 表（自研切分 + jieba 分词）。换成 LlamaIndex 后向量写在
`data_kb_nodes`，旧表的数据不再生效，升级后跑一次重建即可：

```bash
cd /opt/open-agent-harness
set -a && . ./.env && set +a      # 必须：PG 口令在 .env 里，手动跑不加载会报 "no password supplied"
PYTHONPATH=. "$HOME/miniforge3/envs/oah/bin/python" -m src.infra.kb.ingest --reindex-all
```

这条命令会：删掉旧 `kb_chunk` 表 → 把所有文档重新排队 → 解析/切分/嵌入/写新表。
原文件留在 `data/kb/`，不会丢；跑完 `/api/kb/stats` 的 `chunks` 就是新表的节点数。

## 3. 起嵌入服务

模型跑在独立环境里，主服务只通过 HTTP 调它。

```bash
# 独立 conda 环境（别装进主环境，onnxruntime 会和主服务抢内存）
"$HOME/miniforge3/bin/conda" create -y -n oah-embed \
    --override-channels -c conda-forge python=3.12
# conda-forge 的 python 默认不带 pip
"$HOME/miniforge3/envs/oah-embed/bin/python" -m ensurepip --upgrade
"$HOME/miniforge3/envs/oah-embed/bin/python" -m pip install -q -r requirements-embed.txt
```

### 3.1 先解决模型下载（重要，否则会卡死）

默认模型是 **`intfloat/multilingual-e5-large`（1024 维，2.24 GB）**，多语言里最强的一档。
它有两条下载路线：

**A. 能连内网镜像（推荐，实测可用）**：先允许联网跑一次，下完就锁回离线。

```bash
# 临时去掉离线开关（drop-in 里加一行），重启让它自己下
sudo tee /etc/systemd/system/pa-kb-embed.service.d/20-embed.conf >/dev/null <<'CONF'
[Service]
Environment=EMBED_MODEL=intfloat/multilingual-e5-large
Environment=HF_HUB_OFFLINE=0
CONF
sudo systemctl daemon-reload && sudo systemctl restart pa-kb-embed
# 2.24 GB，hf-mirror 实测约 3 MB/s；`systemctl status` 里会停在 startup，属正常
watch -n 20 'curl -s localhost:5110/health'

# 下完后把缓存挪到持久目录，并锁回离线（/tmp 重启即丢）
sudo systemctl stop pa-kb-embed
sudo mkdir -p /var/lib/oah-embed && sudo mv /tmp/fastembed_cache/* /var/lib/oah-embed/
sudo tee /etc/systemd/system/pa-kb-embed.service.d/20-embed.conf >/dev/null <<'CONF'
[Service]
Environment=EMBED_MODEL=intfloat/multilingual-e5-large
Environment=FASTEMBED_CACHE_PATH=/var/lib/oah-embed
Environment=HF_HUB_OFFLINE=1
CONF
sudo systemctl daemon-reload && sudo systemctl start pa-kb-embed
```

**B. 完全离线**：用 curl 把文件灌进 `FASTEMBED_CACHE_PATH` 的 HF 缓存目录。
e5-large 在 fastembed 里的 HF 仓库是 `qdrant/multilingual-e5-large-onnx`
（可用 `TextEmbedding.list_supported_models()` 查 `sources`）。

```bash
REPO=xenova/paraphrase-multilingual-mpnet-base-v2   # 该模型在 fastembed 里的 HF 仓库
REV=e5d116277351513fd260955ece953ecddde7046e        # 仓库当前 commit
DEST=/var/lib/oah-embed
SNAP=$DEST/models--xenova--paraphrase-multilingual-mpnet-base-v2/snapshots/$REV
sudo mkdir -p "$SNAP/onnx"

for f in config.json tokenizer.json tokenizer_config.json special_tokens_map.json; do
  sudo curl -fsSL -o "$SNAP/$f" "https://hf-mirror.com/$REPO/resolve/main/$f"
done

# 大文件：断点续传循环（镜像会中途 reset，单次经常只到 200/1100 MB）
sudo bash -c "for i in \$(seq 1 15); do
  curl -sS -L -C - -o '$SNAP/onnx/model.onnx' \
       'https://hf-mirror.com/$REPO/resolve/main/onnx/model.onnx' && break
done"
```

然后装服务并启动（单元文件已设好缓存路径与离线开关）：

```bash
sudo cp deploy/pa-kb-embed.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now pa-kb-embed
sleep 20 && curl -s http://127.0.0.1:5110/health     # 期望 dim=1024
```

**这两个环境变量必须有**：

| 变量 | 不加的后果 |
|---|---|
| `FASTEMBED_CACHE_PATH=/var/lib/oah-embed` | fastembed 默认放 `$TMPDIR/fastembed_cache`，重启/清 tmp 后要重下 1.1 GB |
| `HF_HUB_OFFLINE=1` | 每次启动都去校验重下，卡在 0% 不返回 |

另开一个终端验证：

```bash
curl -s localhost:5110/health
# {"ok":true,"embedding_model":"intfloat/multilingual-e5-large","dim":1024,...}

# e5 系列必须带 kind：query 走 "query: " 前缀，文档走 "passage: "
curl -s localhost:5110/embed -H 'Content-Type: application/json' \
     -d '{"texts":["天津市2023年地区生产总值"],"kind":"query"}' | head -c 120
```

> **模型选择有个坑**：`fastembed` 只支持固定清单里的模型（`TextEmbedding.list_supported_models()`）。
> `BAAI/bge-m3` **不在**清单里；中文可选的是 `intfloat/multilingual-e5-large`（1024 维，2.24 GB）、
> `BAAI/bge-small-zh-v1.5`（512 维，512 token 上限）、
> `sentence-transformers/paraphrase-multilingual-mpnet-base-v2`（768 维，旧默认）。
> 换模型必须同步改 `[kb] dim` 并重建索引（维度变了旧表用不了）。
> 想换别的模型，先 `TextEmbedding.list_supported_models()` 看名字和维度，**维度必须和配置里的 `dim` 一致**。

**重排要不要开？没有 GPU 就关掉。** 实测（8 核 CPU）：

| 场景 | 嵌入延迟 | 内存 |
|---|---|---|
| 只加载嵌入模型（`RERANK_MODEL=none`） | **0.32 s/次** | 约 600MB |
| 同时加载重排 `bge-reranker-base` | **8 s/次**（两个模型抢 CPU） | 打满 2G |

而且 20 段重排要 3.2 秒，而检索侧的重排超时只有 200ms，等于白占资源。所以 CPU 机器上：

```bash
# systemd unit 的 [Service] 段里加（注意别写到 [Install] 下面，会被忽略）
Environment=RERANK_MODEL=none
```

有 GPU 或机器够强时再去掉这行；重排加载要 20~30 秒，服务在后台线程预热，不会挡查询。

## 4. 配主服务

**4.1 `config/configs.cfg` 的 `[kb]` 段**

```ini
[kb]
enabled = true
pg_db = kb
embed_url = http://127.0.0.1:5110
dim = 1024               # 必须和嵌入模型的实际维度一致（e5-large=1024，mpnet=768）
max_file_mb = 20
data_dir =               # 留空 = <仓库>/data/kb（OCR 缓存也在这里）
```

**4.2 `.env`**

```bash
# kb 库和主库同一实例、同一个 postgres 账号时可以不写（自动复用 [agent] 的 pg 口令）
PA_KB_PG_PASS='PG密码'

# 只用得上扫描件 OCR 才需要（见 §6）
PA_KB_OCR_API_KEY='视觉网关的key'
```

前缀规则：`.env` 变量名是 `PA_` + **section 名大写** + 配置项名，所以 `[kb] pg_pass` → `PA_KB_PG_PASS`。

**4.3 重启并验证**

```bash
sudo systemctl restart open-agent-harness     # 服务名以 install.sh 装的为准
curl -s -b cookies.txt http://127.0.0.1:5001/open-agent-harness/api/kb/stats
```

期望：

```json
{"ok":true,"docs":0,"chunks":0,"failed":0,"pending":0,
 "embed":{"ok":true,"detail":{"dim":1024,"embed_error":"","rerank_error":""}}}
```

`embed.ok=false` 说明主服务连不上 5110，先看嵌入服务日志。

## 5. 索引怎么跑（上传即触发，无需定时任务）

上传只做两件事：存文件、写一条 `kb_task`。真正的解析/切分/嵌入在**独立进程**里跑，
不会占住上传请求（扫描件 OCR 要 20 秒/页，30 页就是 10 分钟）。

触发点有三个，都在代码里，不用配 cron：

| 触发 | 说明 |
|---|---|
| 上传成功 | 接口立刻调 `systemd-run --unit=pa-kb-index-now` 起一次性 worker |
| 点「重建」 | 同上（重新解析、重新嵌入） |
| 服务启动 | 若队列里有 `pending`，启动时补跑一次（部署/重启不丢任务） |

固定 unit 名保证**同一时刻只有一个 worker**；多人同时上传时后来者被 systemd 拒绝，
正在跑的那个 worker 会把任务表里的新任务一起捡走（`FOR UPDATE SKIP LOCKED` 防重复）。

手动跑一批（调试用）：

```bash
cd /opt/open-agent-harness
PYTHONPATH=. "$HOME/miniforge3/envs/oah/bin/python" -m src.infra.kb.ingest --once
```

查看 worker 日志：`journalctl -u pa-kb-index-now -n 50 --no-pager`（Popen 兜底时写在 `data/kb/ingest.log`）。

> 页面上状态会依次变化：`排队中 → 解析中 →（扫描件）OCR 识别中 → 索引中 → 可用`，
> 失败的会写明原因。**没有定时器**，所以卡住的文档点「重建」就会重跑；
> worker 被 kill 导致任务停在 `running` 时，10 分钟后会被下一个 worker 当僵尸任务重新捡起。

## 6. 扫描件 OCR（可选）

没有文字层的扫描 PDF，默认会 `failed` 并写明"需要 OCR"。要支持就接一个
**OpenAI 协议的视觉接口**（`/chat/completions` + `image_url`）：

```ini
[kb]
ocr_enabled = true
ocr_base_url = https://你的视觉网关/v1
ocr_model = 你的视觉模型名
ocr_dpi = 150          # 150 够用；调高更清晰但更慢
ocr_max_pages = 30     # 超过的页不 OCR，防止几百页扫描书打满网关
ocr_timeout_s = 120
```

```bash
PA_KB_OCR_API_KEY='sk-xxx'      # 写进 .env
```

工作机制：

| 情况 | 行为 |
|---|---|
| 页面有文字层（≥40 字） | 直接用 PDF 里的文字，**不调模型** |
| 页面无文字层 | 渲染成 PNG → 视觉模型 → 文本 |
| 识别结果 | 缓存到 `data/kb/ocr/<doc_id>/p<页码>.txt`，重索引不重复调用 |
| 单页失败 | 跳过继续下一页；**一页都没成功**才整篇 failed |
| 耗时 | 实测约 **20 秒/页**（150dpi，中文统计公报） |

## 8. 排查

| 现象 | 原因 / 处理 |
|---|---|
| 启动报 `type "vector" does not exist` | 没装 pgvector 或没在 `kb` 库里 `CREATE EXTENSION vector` |
| `/api/kb/*` 全 404 | `[kb] enabled = false` |
| `embed.ok=false` | 5110 没起；看 `systemctl status pa-kb-embed` |
| 写库报 `expected N dimensions` | 换了嵌入模型但 `dim` 没改，或旧表维度不同 → 改 `dim`、`DROP TABLE data_kb_nodes` 后 `ingest --reindex-all` |
| 文档一直 `embedding` | worker 被 kill；点「重建」立刻重跑（或等 10 分钟僵尸回收） |
| 文档 `failed` 且提示 `需要 OCR` | 扫描件；按 §6 配 OCR |
| 文档 `failed` 且提示 `PostgreSQL text fields cannot contain NUL` | 老版本 bug，已修（解析层去控制字符） |
| `rerank_error: Model '' is not supported` | 重排没配模型，属正常降级（不报错，只是排序略差） |
| 检索"答得上但排序不理想" | 未启用重排；或文档太多需要把 `top_k` 调大 |

## 9. 卸载 / 清理

```bash
sudo systemctl disable --now pa-kb-embed pa-kb-index.timer
sudo -u postgres psql -c "DROP DATABASE kb;"       # 所有向量和文档记录
rm -rf /opt/open-agent-harness/data/kb             # 原始文件 + OCR 缓存
# configs.cfg 里 [kb] enabled = false 即可让接口和 kb_search 工具失效
```
