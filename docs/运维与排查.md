## 1. 加人 / 改密码 / 调权限

**加人**：系统设置 → 用户管理 → 新增用户。
不选角色 = 公共角色，不填密码 = `123456`。接口版：

```bash
BASE=http://127.0.0.1:5001/open-agent-harness
curl -c ck -o /dev/null -X POST -d 'username=admin&password=admin' "$BASE/login"
curl -b ck -X POST "$BASE/api/users" -H 'Content-Type: application/json' \
  -d '{"username":"alice","display_name":"Alice","roles":["default"],"password":"InitPass1"}'
```

**改密码**：用户点左下角钥匙图标（旧密码 + 新密码）；
管理员重置：用户管理 → 重置密码，或 `POST /api/users/{账号}/password`（空 = 123456）。

**调权限**：系统设置 → 角色管理，勾工具。保存即生效，不用重启。

**角色**：只有「管理员」和「公共角色」不可删，其他角色状态、工具都可改可删。

## 2. 可选组件

改 `.env` 后 `sudo systemctl restart open-agent-harness`。

**PostgreSQL**（对话上下文持久化，**必装**：lifespan 里要连它，连不上服务直接退出）

> 只有 Redis / 沙箱是可选的，PG 不是。

```ini
PA_AGENT_PG_HOST=127.0.0.1
PA_AGENT_PG_DB=agent_state
PA_AGENT_PG_USER=postgres
PA_AGENT_PG_PASS=PG密码
```

**Redis**（权限缓存 / 限流 / 防重复提交）

```ini
PA_REDIS_REDIS_HOST=127.0.0.1
PA_REDIS_REDIS_PASSWORD=Redis密码
PA_REDIS_REDIS_CLUSTER=false      # 集群填 true
```

**沙箱**（模型能执行命令、读写文件、出报表）

```ini
# config/configs.cfg
[agent]
openshell_enabled = true
openshell_bin = /snap/bin/openshell
openshell_image = pa-sandbox:1.3
sandbox_memory = 1Gi          # 只能写 512Mi / 1Gi / 8G，写 1GiB 会被拒（参数非法）
```

不开沙箱也能用，只是没有执行类工具。

### 2.1 首次部署沙箱（一次性，约 40 分钟）

OpenShell 0.1.x 是 gateway 架构：snap 里跑 gateway，gateway 调 Docker 起容器，
容器镜像必须是本地构建好的 `pa-sandbox:1.3`。

```bash
# 1. 运行环境（gateway 依赖 Docker；构建依赖 buildx）
sudo snap install openshell
sudo apt install -y docker.io docker-buildx
sudo systemctl enable --now docker
sudo snap start --enable openshell.system-gateway

# 2. 注册本地 gateway
#    CLI 去 $HOME/snap/openshell/common/.config/openshell/gateways/openshell/mtls/ 找证书，
#    而 gateway 把证书生成在 /var/snap/openshell/common/tls/ —— 打包上没接上，要手工拷一次
D=$HOME/snap/openshell/common/.config/openshell/gateways/openshell/mtls
install -d -m700 "$D"
install -m400 /var/snap/openshell/common/tls/ca.crt "$D/ca.crt"
install -m400 /var/snap/openshell/common/tls/client/tls.crt "$D/tls.crt"
install -m400 /var/snap/openshell/common/tls/client/tls.key "$D/tls.key"
openshell gateway add --local https://127.0.0.1:17670
openshell status                      # 期望 Connected / Authenticated (mTLS)

# 3. 构建沙箱镜像（**必须** BuildKit，否则 heredoc 全部静默失效，中文变豆腐块）
cd /opt/open-agent-harness
sudo DOCKER_BUILDKIT=1 docker build -t pa-sandbox:1.3 -f docker/pa-sandbox.Dockerfile .
#   产物约 7.3 GB；最后会打印一串 ✅ 自检（Python 库 / 中文字体 / Chromium / 空 ENV 仿真）

# 4. 冒烟测试：起一个沙箱跑条命令
sudo openshell sandbox create --name smoke --from pa-sandbox:1.3 --no-keep -- \
     python3 -c "import pandas; print(pandas.__version__)"

# 5. 打开开关并重启服务（.env 的变量名是 PA_AGENT_*，前缀取自 [agent] 段）
echo 'PA_AGENT_OPENSHELL_ENABLED=true' | sudo tee -a /opt/open-agent-harness/.env
sudo systemctl restart open-agent-harness
```

> `openshell doctor check` 会报 "failed to execute docker info"：snap 严格沙箱看不到宿主
> `/usr/bin/docker`，属误报，gateway 实际能正常拉镜像起容器，忽略即可。
>
> 服务跑起来后每个用户一个 `agent-<用户名>` 沙箱（`openshell sandbox list` 查看）。
> 闲置停机靠 `deploy/install-maintenance-timers.sh` 里的 `pa-sandbox-idle.timer`，记得装。

### 2.2 知识库（文档 RAG）现状与运维

完整部署步骤见 [`知识库部署说明.md`](知识库部署说明.md)，这里只记**日常运维**。

| 组件 | 位置 / 端口 | 说明 |
|---|---|---|
| 嵌入服务 | `pa-kb-embed` → `127.0.0.1:5110` | 独立进程，768 维，重排默认关（CPU 机器上会拖慢 5 倍） |
| 模型缓存 | `/var/lib/oah-embed` | 1.2 GB，**不要清**，清掉要重下 |
| 知识库 DB | PostgreSQL `kb` 库 | 扩展 `vector` + `pg_trgm`，表 `kb_doc` / `kb_chunk` / `kb_task` 自动建 |
| 嵌入环境 | `~/miniforge3/envs/oah-embed` | 与主环境分开，避免 onnxruntime 抢内存 |
| 开关 | `.env` 的 `PA_KB_ENABLED` | 关掉后 `/api/kb/*` 返 404，`kb_search` 工具拒绝 |

常用命令：

```bash
systemctl status pa-kb-embed
curl -s http://127.0.0.1:5110/health        # 期望 ok=true, dim=768
curl -s http://127.0.0.1:5001/open-agent-harness/api/kb/stats   # 需要登录态

# 重建索引（某篇文档）
curl -X POST -b cookie.txt http://127.0.0.1:5001/open-agent-harness/api/kb/docs/1/reindex

# 清 conda 缓存（不是模型缓存）
"$HOME/miniforge3/bin/conda" clean -a -y
```

排查：

| 现象 | 原因 | 处理 |
|---|---|---|
| stats 里 `embed.ok=false` | 嵌入服务挂了或在加载模型 | `systemctl status pa-kb-embed`、`journalctl -u pa-kb-embed -n 50` |
| 上传后一直 `pending` | 索引任务没跑（上传即触发，失败会留 pending） | 重启主服务会补跑；仍不动看 `kb_task` 表的 error 字段 |
| 启动日志卡在 `Fetching 5 files: 0%` | `HF_HUB_OFFLINE=1` 被删了，或模型缓存丢了 | 确认单元文件里这两个变量，按知识库文档重灌模型 |
| 内存吃紧 | 嵌入模型约 1 G + 3 worker | 先降 `WORKERS`，或给虚拟机加内存 |

## 3. 升级

```bash
cd /opt/open-agent-harness
git pull
sudo PA_DB_MYSQL_PASS='你的数据库密码' PA_LLM_DEEPSEEK_API_KEY='sk-xxx' bash deploy/install.sh
bash deploy/verify.sh        # 验收：服务/健康/前端/单测/日志
```

> ⚠️ `frontend/dist` 不在 git 里。只改后端时 `git pull` 不影响前端；
> 改过前端必须 `cd frontend && npm ci && npm run build`。
> 页面报 `{"error":"前端未构建: index.html"}` 就是 dist 没了。

旧版本升级上来的账号没有密码（`password_hash` 为空），登录会提示「该账号尚未设置密码」，
由管理员重置一次即可。

## 4. 排查

| 现象 | 原因 / 处理 |
|---|---|
| 服务起来又挂 | `.env` 路径不对、端口被占：`journalctl -u open-agent-harness -n 50` |
| 页面白屏 / 502 | dist 没构建：`ls frontend/dist/index.html` |
| 登录提示「用户名或密码错误」 | 账号不存在、密码错、账号被停用 → 管理员重置密码 |
| 登录提示「该账号尚未设置密码」 | 老账号，管理员重置一次 |
| 发消息不出字 | 模型 key / base_url 错：`grep -i 'llm\|401' logs/app.log` |
| 刷新后上下文丢了 | PG 没配或连不上 |
| 工具在但模型不调用 | 该角色没勾这个工具 → 角色管理勾选后重新登录 |

日志：`logs/app.log`（应用）、`journalctl -u open-agent-harness -f`（服务层）。

## 5. 配置在哪改

| 位置 | 放什么 |
|---|---|
| `config/configs.cfg`（入库） | 地址、端口、模型名、开关、阈值 |
| `.env`（不入库，权限 600） | **所有口令和密钥** |

变量名规则 `PA_<段>_<键>`（大写），环境变量优先于配置文件。

| 想改 | 改哪里 |
|---|---|
| 数据库连接 | `config/configs.cfg` `[db]` 或 `PA_DB_MYSQL_*` |
| 模型/网关 | `[llm] deepseek_model` / `deepseek_base_url` |
| 端口 | 单元文件 `ExecStart --port`，或 `PORT=8080 bash deploy/install.sh` |
| 默认角色 | `[app] default_role`（默认 `default` = 公共角色） |
| 报错显示细节 | `[app] error_detail`（默认 false） |
