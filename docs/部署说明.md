# 部署说明

> 服务端已从 Flask 迁到 FastAPI + 全链路异步，本文是**部署视角**；
> 改造细节（阶段、契约、踩坑、回滚）见 [`迁移说明-Flask到FastAPI.md`](迁移说明-Flask到FastAPI.md)。

从零到能对话。**照着敲就行**，全程 20~30 分钟（主要是下依赖）。

- 只想先跑起来看看 → 直接看 [§2 一键部署](#2-一键部署推荐)
- 想把每一步都搞清楚 → 看 [§3 手动部署](#3-手动部署逐步骤)
- 卡住了 → 看 [§9 故障排查](#9-故障排查)

## 1. 先确认你要装什么

| 组件 | 必需 | 不装会怎样 |
|---|---|---|
| Python 3.11+（推荐 3.12） | ✅ | 跑不起来 |
| MySQL 8.0 | ✅ | 跑不起来（会话、账号、权限、审计都在这里） |
| Node.js 18+ | ✅ 必需 | 前端**没有预构建产物**（`frontend/dist` 不入库），没 node 就打不开页面 |
| PostgreSQL 14+ | 🟡 建议 | 能跑，但**刷新/重启后对话上下文丢失** |
| Redis 6+ | 🟡 建议 | 能跑，权限每次查库、限流失效，并发高时变慢 |
| OpenShell + Docker | 🟡 可选 | 能跑，但**不能读文件/跑命令/生成报表**（只剩聊天和纯计算类工具） |

一句话：**MySQL + 模型 key 是硬门槛，其余都能后补。**

## 2. 一键部署（推荐）

```bash
git clone https://github.com/cuijiejie/open-agent-harness.git /tmp/oah && cd /tmp/oah

# 先把数据库建好（只需一次，密码自己定）
mysql -uroot -p -e "
CREATE DATABASE open_agent_harness DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'agent'@'%' IDENTIFIED BY '你的数据库密码';
GRANT ALL PRIVILEGES ON open_agent_harness.* TO 'agent'@'%';
FLUSH PRIVILEGES;"

# 走一键安装（会自动建 venv、装依赖、构建前端、生成 .env、装 systemd、探活）
sudo PA_DB_MYSQL_PASS='你的数据库密码' \
     PA_LLM_DEEPSEEK_API_KEY='sk-你的模型key' \
     bash deploy/install.sh
```

装完打开 `http://<服务器IP>:5001/open-agent-harness/` 就能登录。

> **还差一步**：脚本不会自动建管理员账号。首次部署请按 [3.7 初始化管理员账号](#37-初始化管理员账号首次部署必做) 跑一次 `deploy/seed_admin.py`（默认密码 `admin`），登录后立刻改掉。

**自定义路径与端口：**

```bash
sudo APP_DIR=/srv/agent PORT=8080 \
     PA_DB_MYSQL_PASS=xxx PA_LLM_DEEPSEEK_API_KEY=sk-xxx \
     bash deploy/install.sh
```

> 脚本是**幂等**的：再跑一次就是升级（重装依赖 → 重建前端 → 重启服务 → 探活）。
> 已有的 `.env` 不会被覆盖。

## 3. 手动部署（逐步骤）

每步后面都有「怎么确认这一步成了」。

### 3.1 放代码

```bash
sudo mkdir -p /opt/open-agent-harness
sudo cp -a . /opt/open-agent-harness/     # 或 git clone 到该目录
cd /opt/open-agent-harness
```

✅ 确认：`ls` 能看到 `requirements.txt`、`config/`、`frontend/`

### 3.2 Python 环境

```bash
python3.12 -m venv .venv     # 只有 3.11/3.13 也行：换成对应命令
source .venv/bin/activate
pip install -U pip
pip install -r requirements.txt
```

✅ 确认：`python -c "import fastapi, uvicorn, langgraph, deepagents, psycopg, asyncmy; print('ok')"`

> **装依赖慢 / 超时**（pypi.org 在国内常抽风）：换源即可，一键脚本和手动命令都认这两个变量：
>
> ```bash
> export PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
> export PIP_TRUSTED_HOST=mirrors.aliyun.com
> ```
>
> npm 同理：`npm config set registry https://registry.npmmirror.com`

> `deepagents` / `langgraph` / `langgraph-checkpoint-postgres` 三个版本互相咬合，
> 按 `requirements.txt` 装，别单独升其中一个。

### 3.3 建库

```sql
CREATE DATABASE open_agent_harness
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'agent'@'%' IDENTIFIED BY '你的数据库密码';
GRANT ALL PRIVILEGES ON open_agent_harness.* TO 'agent'@'%';
FLUSH PRIVILEGES;
```

**表不用建**：服务启动（或 `deploy/seed_admin.py` 第一次运行）时会自动建表并补列，
其余表（`pa_tools` 等）首次用到时自建。不需要跑任何 SQL 初始化脚本。

具体建了什么见 [3.8 初始化数据一览](#38-初始化数据一览部署完成后库里有什么)。

✅ 确认：`mysql -uagent -p open_agent_harness -e "select 1"`

### 3.4 配置密钥

配置文件是 `config/configs.cfg`（已入库，只放**非敏感项**）；
**所有口令/密钥都走环境变量**，写在 `.env` 里由 systemd 注入：

```bash
cat > /opt/open-agent-harness/.env <<'EOF'
# ---- 必填 ----
PA_DB_MYSQL_PASS=你的数据库密码
PA_LLM_DEEPSEEK_API_KEY=sk-你的模型key
PA_APP_SECRET_KEY=用下面的命令生成

# ---- MySQL 其他项（默认值可用时可省略）----
# PA_DB_MYSQL_HOST=127.0.0.1
# PA_DB_MYSQL_PORT=3306
# PA_DB_MYSQL_USER=agent
# PA_DB_MYSQL_DB=open_agent_harness

# ---- PostgreSQL（对话上下文持久化，可选）----
# PA_AGENT_PG_HOST=127.0.0.1
# PA_AGENT_PG_PORT=5432
# PA_AGENT_PG_DB=agent_state
# PA_AGENT_PG_USER=postgres
# PA_AGENT_PG_PASS=PG密码

# ---- Redis（权限缓存/限流/去重，可选）----
# PA_REDIS_REDIS_HOST=127.0.0.1
# PA_REDIS_REDIS_PORT=6379
# PA_REDIS_REDIS_PASSWORD=Redis密码
# PA_REDIS_REDIS_DB=0
# PA_REDIS_REDIS_CLUSTER=false

# ---- 默认角色（可选，默认 default=公共角色）----
# PA_APP_DEFAULT_ROLE=default
EOF
chmod 600 /opt/open-agent-harness/.env

# 生成 session 密钥
python3 -c "import secrets;print(secrets.token_hex(32))"
```

✅ 确认：`grep -c '^PA_' .env` 至少 3 个

### 3.5 构建前端

```bash
cd frontend
npm ci
npm run build      # 产物 frontend/dist
cd ..
```

✅ 确认：`ls frontend/dist/index.html`

### 3.6 启动

**开发/试跑：**

```bash
source .venv/bin/activate
PYTHONPATH=. python -m uvicorn src.app_fastapi:app --host 0.0.0.0 --port 5001 --workers 4
```

**生产（systemd）：**

```bash
sudo cp deploy/open-agent-harness.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now open-agent-harness
```

✅ 确认：

```bash
systemctl is-active open-agent-harness          # active
grep 'RBAC 表就绪' logs/app.log | tail -1        # RBAC 表就绪（权限只来自数据库：pa_roles / pa_user_roles / pa_users）
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5001/open-agent-harness/api/health   # 200
```

> 装到别的目录要改单元文件里的 3 处路径（`WorkingDirectory`、`Documentation`、`ExecStart`），
> 或用一键脚本自动替换。

### 3.7 初始化管理员账号（首次部署必做）

**角色不用你建。** 首次启动时 `admin` 角色已随预置角色写进 `pa_roles`
（`tools = ["*"]`、`is_admin = 1`、内置不可删）。你只需要建**用户**并给它设密码。

> 系统**不会**在启动时自动建管理员账号 —— 否则每次部署都会凭空多出一个默认口令的管理员入口。
> 而登录现在要求"账号存在 + 密码正确"，没有账号谁也进不去，所以这一步必须显式做一次。

**一条命令完成（推荐）**

```bash
cd /opt/open-agent-harness          # 换成你的 APP_DIR
PYTHONPATH=. .venv/bin/python deploy/seed_admin.py
```

它会：建 `admin` 用户 → 挂 `admin` 角色 → 设置密码 **`admin`**（已有密码则不覆盖）。
幂等，可重复执行。

| 目的 | 命令 |
|---|---|
| 换一个密码 | `PYTHONPATH=. .venv/bin/python deploy/seed_admin.py --password 'N3wPass!'` |
| 已有密码也强制重置 | `PYTHONPATH=. .venv/bin/python deploy/seed_admin.py --force-reset` |
| 换个账号名 | `PYTHONPATH=. .venv/bin/python deploy/seed_admin.py --username zhangsan` |

**登录后第一件事：改掉默认密码**

```bash
# 管理员重置任意账号的密码（不传 password 则重置为默认 123456）
curl -b "session=<cookie>" -X POST \
  http://127.0.0.1:5001/open-agent-harness/api/users/admin/password \
  -H 'Content-Type: application/json' -d '{"password":"NewPass2026!"}'
```

**谁能登录、默认密码是什么**

| 身份 | 默认密码 | 说明 |
|---|---|---|
| 首个管理员（`seed_admin.py` 创建） | `admin` | 登录后立即修改 |
| 管理员在「用户管理」里新建的用户 | `123456` | 建号时可自定义密码；忘记密码由管理员重置 |
| 从旧版本升级的存量账号 | **无** | 必须先由管理员重置一次才能登录（旧的"输入用户名即可登录"已关闭） |

> 密码以 bcrypt（cost=12）哈希存于 `pa_users.password_hash`，数据库里没有明文。
> 登录失败统一提示「用户名或密码错误」，不区分账号是否存在。

**默认角色 = 公共角色**

启动时（`ensure_schema`）保证存在内置角色 **`default`（显示名「公共角色」）**，
工具取「公共工具」（工具管理里勾了「公共」的那些，单一口径 `pa_tools.always_on`：
`ask_user`、记忆类工具、`sandbox_shell` 等）。

- 管理员新增用户时**不选角色**，后端自动挂 `default`
- 页面「新增用户」的默认勾选来自后端 `[app] default_role`（默认 `default`）
- 需要更多权限时，再把用户加到 `operator` / 自定义角色上

**哪些角色不能删**

| 角色 | 编码 | 内置（不可删） | 说明 |
|---|---|---|---|
| 管理员 | `admin` | ✅ | 删了没人能进角色管理 |
| 公共角色 | `default` | ✅ | 删了新建用户会落到"无角色" |
| 操作员 | `operator` | ❌ 可删 | 只是预置示例，按需保留或删除 |
| 查看者 | `viewer` | ❌ 可删 | 只是预置示例，按需保留或删除 |

启动时（`ensure_schema`）会把 `admin` 与默认角色强制标记为内置，
并把 `operator`/`viewer` 的「内置」标记清掉 —— 老库曾经把四个预置角色全写成内置，
重启一次即自动纠正。删除时仍会检查"是否还有用户在使用"。

### 3.8 初始化数据一览（部署完成后库里有什么）

跑完 3.7 之后，数据库里**只有下面这些**，不含任何演示数据。

**角色表 `pa_roles`（4 行，首次启动自动写入）**

| 显示名 | 编码 | 内置 | 工具 |
|---|---|---|---|
| 管理员 | `admin` | ✅ 不可删 | `*`（全部工具 + 角色分配） |
| 公共角色 | `default` | ✅ 不可删 | 公共工具（见下），新建用户的默认角色 |
| 操作员 | `operator` | ❌ 可删 | `ask_user`、`sandbox_shell` |
| 查看者 | `viewer` | ❌ 可删 | `ask_user` |

「公共工具」= 工具管理里勾了「公共」的那些，口径为 `pa_tools.always_on`。
全新部署默认是：`ask_user`、`remember_fact`、`remember_preference`、`forget_fact`、
`forget_preference`、`sandbox_shell`。

**用户表 `pa_users` / `pa_user_roles`**

| 账号 | 密码 | 角色 | 说明 |
|---|---|---|---|
| `admin` | `admin`（bcrypt 哈希存 `password_hash`） | 管理员 | 由 `deploy/seed_admin.py` 创建 |

除此之外**没有别的账号**。新用户由管理员在「用户管理 → 新增用户」创建：
不选角色 → 自动挂公共角色；不填密码 → 默认 `123456`。

**核对命令（部署后值得跑一次）**

```bash
cd /opt/open-agent-harness && set -a && . ./.env && set +a
PYTHONPATH=. .venv/bin/python -c "
from src.infra.RbacService import rbac
print('角色：')
for r in rbac.list_roles():
    print('  %-6s %-9s 内置=%-5s 工具=%s' % (r['role_name'], r['role_code'], r['is_builtin'], r['tools']))
print('用户：')
for u in rbac.page_users('', '', 1, 50)['users']:
    print('  %-10s 角色=%s 状态=%s' % (u['username'], u['roles'], u['status']))
"
```

期望：角色 4 行（`admin`/`default` 内置=True，`operator`/`viewer` 内置=False），用户 1 行（`admin`）。

## 5. 配置速查

两个地方，分工不重叠：

| 位置 | 放什么 | 例子 |
|---|---|---|
| `config/configs.cfg`（入库） | 地址、端口、模型名、开关、阈值 | `mysql_host`、`deepseek_model`、`openshell_enabled` |
| `.env` / 环境变量（不入库） | **所有口令与密钥** | `PA_DB_MYSQL_PASS`、`PA_APP_SECRET_KEY` |

变量名规则：`PA_<SECTION>_<KEY>`（大写）。优先级：**环境变量 > 配置文件 > 代码默认值**。

### 5.1 最常改的几个

| 想改什么 | 改哪里 | 怎么改 |
|---|---|---|
| 数据库地址/库名 | `config/configs.cfg` `[db]` | 直接改，或 `PA_DB_MYSQL_HOST` 覆盖 |
| 用别的模型/网关 | `[llm] deepseek_model / deepseek_base_url` | 任何 OpenAI 协议网关都行 |
| 端口 | 单元文件 `ExecStart` 里的 `--port` | 或 `PORT=8080 bash deploy/install.sh` |
| 用户密码 | 数据库 `pa_users.password_hash` | bcrypt 哈希；初始密码见 3.7 |
| 免密直登入口 | ~~`[app] test_login_enabled`~~ | **已删除**（`/test-login` 端点不再存在） |
| 报错要不要显示细节 | `[app] error_detail` | 默认 false（只给通用提示） |
| 开沙箱 | `[agent] openshell_enabled` | 见 §6.1 |

## 6. 可选组件

### 6.1 沙箱（让模型能读文件、跑命令、出报表）

```ini
[agent]
openshell_enabled = true
openshell_bin = /snap/bin/openshell
openshell_image = pa-sandbox:1.3
```

```bash
# 镜像自建（预装 pandas / openpyxl / matplotlib / python-docx）
sudo docker build -t pa-sandbox:1.3 -f docker/pa-sandbox.Dockerfile .
```

- 每个用户一个容器，**登录时后台创建**，闲置 7 天只 `stop`（文件全留），用户被删才 `delete`
- `config/sandbox-policy.yaml` 默认**拒绝所有出站**，要访问外部 API/内网库需显式放行
- 不开沙箱时 `sandbox_shell` 会明确报错，对话与插件工具照常

### 6.2 PostgreSQL（对话上下文持久化）

```sql
CREATE DATABASE agent_state;
```

`.env` 里填 `PA_PG_HOST / PA_PG_PASS`，表由程序自建。
连不上会自动降级为内存 checkpointer（日志有 ERROR），**不会导致起不来**。

### 6.3 Redis

`.env` 填 `PA_REDIS_REDIS_HOST / PA_REDIS_REDIS_PASSWORD / PA_REDIS_REDIS_DB`。
不配也能跑，只是权限每次查库。

### 6.4 MCP 服务

```ini
[mcp]
enabled = true
servers = my_tools|python|-m my_mcp_server|API_KEY=xxx
```

只有管理员能在配置里声明，跑在宿主机上，用户不可自装。

## 7. 加人 / 开管理员 / 重置密码

密码登录之后，**账号只能由管理员创建**（登录不再自动建档）：

```bash
BASE=http://127.0.0.1:5001/open-agent-harness

# ① 管理员登录，把会话存到 ck
curl -c ck -o /dev/null -X POST -d 'username=admin&password=admin' "$BASE/login"

# ② 建账号（roles 不传 = 公共角色；password 不传 = 123456）
curl -b ck -X POST "$BASE/api/users" -H 'Content-Type: application/json' \
  -d '{"username":"alice","display_name":"Alice","roles":["admin"],"password":"InitPass1"}'

# ③ 重置密码（仅管理员；不传 password = 重置成 123456）
curl -b ck -X POST "$BASE/api/users/alice/password" \
  -H 'Content-Type: application/json' -d '{"password":"NewPass2026"}'
```

用户也可以自己改密码：登录后点侧栏左下角的**钥匙图标**（旧密码 + 新密码 + 确认），
对应接口 `POST /api/user/password`。

权限改动即时生效（角色保存时会清 Redis 缓存），多 worker 不需要重启。

✅ 确认：新账号登录后左下角显示角色名；用旧密码登录应失败（401）。

## 8. 放在 Nginx 后面

```nginx
location /open-agent-harness/ {
    proxy_pass http://127.0.0.1:5001;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_buffering off;        # SSE 必须关，否则"点了没反应，10 秒后一次性出来"
    proxy_read_timeout 300s;    # 默认 60s 会掐断长任务
    client_max_body_size 50m;   # 附件上传
}
```

## 9. 故障排查

| 现象 | 大概率原因 | 怎么查 |
|---|---|---|
| 服务起不来，`status` 一直 restart | `.env` 路径不对 / 端口被占 | `journalctl -u open-agent-harness -n 50`；`ss -lntp \| grep 5001` |
| 页面 502 / 空白 | 前端没构建 | `ls frontend/dist/index.html` |
| 页面能开，登录后白屏 | 静态资源 404 | 浏览器 F12 → Network 看 `assets/*.js` 状态码 |
| 登录后提示「服务暂时不可用」 | MySQL 连不上 | `grep ERROR logs/app.log \| tail -5` |
| 登录提示「用户名或密码错误」 | 账号不存在 / 密码不对 / 账号被停用 | 管理员重置密码：`POST /api/users/{账号}/password` |
| 登录提示「该账号尚未设置密码」 | 老账号 `password_hash` 为空（从旧版本升级） | 管理员重置一次密码即可 |
| 发消息一直不出字 | 模型 key / base_url 错 | 日志里搜 `LLM` / `401` / `Unauthorized` |
| 报 `table doesn't exist` | 启动时建表失败（数据库权限不足） | 日志搜「数据库自检失败」；给账号补 `CREATE` 权限 |
| 刷新后上下文丢了 | PostgreSQL 没配或连不上 | 日志搜「降级为内存 checkpointer」 |
| 工具在界面但模型不调用 | 该角色没分配这个工具 | 系统设置 → 角色 → 勾选工具 → 重新登录 |
| 改完权限不生效 | 权限缓存 300 秒 TTL | 正常保存会自动清；手工清见 §7 |
| 沙箱命令超时 | 容器太多/没起 | `openshell sandbox list`；跑一次维护任务 |

日志位置：

```
logs/app.log                应用日志（按天切分）
uvicorn 访问/错误           同上（journalctl 里也有一份）
journalctl -u open-agent-harness -f   服务层（启动失败看这里）
```

## 10. 日常运维

### 10.1 升级

```bash
cd /opt/open-agent-harness
git pull
sudo PA_DB_MYSQL_PASS=x PA_LLM_DEEPSEEK_API_KEY=y bash deploy/install.sh   # 幂等，等于升级
```

或手动：

```bash
source .venv/bin/activate && pip install -r requirements.txt
cd frontend && npm ci && npm run build && cd ..
sudo systemctl restart open-agent-harness
bash deploy/verify.sh
```

> ⚠️ **`frontend/dist` 不在 git 里**（`.gitignore` 挡住了）。所以：
> ① 只更新后端代码时，`git checkout/pull` 不会动 dist，前端保持原样；
> ② 但如果某次提交**曾经把 dist 纳入过版本**，之后的 checkout 会把 dist 删掉，
>    页面就会返回 `{"error":"前端未构建: index.html"}`。
> 判断方法：`ls frontend/dist/index.html` 不存在 → 在 `frontend/` 下 `npm ci && npm run build` 重新生成，
> 或从已有的构建产物拷回来。**改过前端就必须重新 build**，dist 不是自动产物。

### 10.2 定时维护（4 个独立 timer，一个任务一件事）

```bash
sudo bash deploy/install-maintenance-timers.sh
systemctl list-timers 'pa-*'
```

| timer | 时间(UTC) | 做什么 |
|---|---|---|
| `pa-logs` | 03:00 | 日志切分 + 删 365 天前 |
| `pa-artifacts` | 03:10 | 删 90 天没动过的交付物副本（沙箱原件不动） |
| `pa-sandbox-idle` | 03:20 | 闲置 7 天 → `sandbox stop`（只停不删） |
| `pa-sandbox-orphan` | 03:30 | 用户已不存在 + 3 天 → `sandbox delete` |

预演（不实际执行）：`python -m src.infra.Maintenance sandbox-idle --dry-run`

### 10.3 备份

```bash
mysqldump -uagent -p --single-transaction open_agent_harness > backup_$(date +%F).sql
# 沙箱里的用户文件在 docker volume 里，如需保留请一并备份
```
