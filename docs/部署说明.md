# 部署说明

一台 Linux 机器，**五步**：装环境 → 建库 → 装程序 → 初始化管理员 → 验证。约 30 分钟。

> 这份文档是自包含的：环境、依赖、数据库、嵌入服务、MCP 接入、验收、排障都在这里。
> 架构设计、运维细则等内部文档不随仓库发布。

---

## 0. 部署形态一览

| 组件 | 作用 | 端口 | 必需 |
|---|---|---|---|
| `open-agent-harness` | 主服务（FastAPI + LangGraph） | 5002 | ✅ |
| `pa-kb-embed` | 文档知识库的嵌入服务（bge-m3 int8） | 5110（仅本机） | 用到知识库才要 |
| `pa-mcp-weather` | MCP 示例服务（可选，演示用） | 5120（仅本机） | ❌ |
| MySQL | 账号 / 会话 / 审计 / 工具元数据 | 3306 | ✅ |
| PostgreSQL | LangGraph checkpoint + 知识库向量 | 5432 | ✅ |
| Redis | 限流、权限快照、缓存 | 6379 | 推荐（不装则降级） |
| 沙箱 | OpenShell 容器，跑用户代码 | — | 用到沙箱才要 |

服务都通过 systemd 管理，代码目录默认 `/opt/open-agent-harness`。

## 1. 装环境

| 必须 | 版本 | 装法 |
|---|---|---|
| Linux | Ubuntu 22.04（其他发行版同理） | — |
| Python | **3.12** | **Miniforge**（见 §1.1，不用 venv） |
| Node.js | 18+ | `curl -fsSL https://deb.nodesource.com/setup_20.x \| sudo -E bash - && sudo apt install -y nodejs` |
| MySQL | 8.0 | `sudo apt install -y mysql-server` |
| PostgreSQL | 14+ | `sudo apt install -y postgresql`（**必装**：连不上服务直接退出） |
| Redis（推荐） | 6+ | `sudo apt install -y redis-server` |
| 模型 API Key | OpenAI 协议即可 | 公司网关或官方 Key |

py 依赖下载慢先 `export PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/`。

### 1.1 装 Miniforge（Python 3.12）

```bash
# x86_64 用 Miniforge3-Linux-x86_64.sh；aarch64 换成 aarch64
curl -fsSLO https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh
bash Miniforge3-Linux-x86_64.sh -b -p "$HOME/miniforge3"

"$HOME/miniforge3/bin/conda" create -y -n oah --override-channels -c conda-forge python=3.12
"$HOME/miniforge3/envs/oah/bin/python" -V      # 期望 3.12.x
```

细节（conda/pip 混用规矩、验收、回滚、踩坑）见 [`Conda环境.md`](Conda环境.md)。

## 2. 建库

**2.1 MySQL（业务库）**

```sql
CREATE DATABASE open_agent_harness DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'agent'@'%' IDENTIFIED BY '「数据库密码」';
GRANT ALL PRIVILEGES ON open_agent_harness.* TO 'agent'@'%';
FLUSH PRIVILEGES;
```

表不用手建，服务启动时自动创建/迁移。

**2.2 PostgreSQL（检查点 + 知识库）**

```bash
sudo -u postgres psql \
  -c "ALTER USER postgres PASSWORD '「PG密码」';" \
  -c "CREATE DATABASE open_agent_harness;"

# 用到文档知识库时再建一个（向量表在服务启动时自动建）
sudo -u postgres psql -c "CREATE DATABASE kb;"
sudo -u postgres psql -d kb -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

> PG 需要 pgvector 扩展（Ubuntu 装 `postgresql-14-pgvector` 之类的对应版本包）。

## 3. 装程序

```bash
git clone https://github.com/cuijiejie/open-agent-harness.git /opt/open-agent-harness
cd /opt/open-agent-harness

sudo PA_DB_MYSQL_PASS='「数据库密码」' \
     PA_AGENT_PG_PASS='「PG密码」' \
     PA_LLM_DEEPSEEK_API_KEY='sk-「模型key」' \
     USE_CONDA=1 \
     CONDA_PREFIX_DIR="$HOME/miniforge3" CONDA_ENV=oah \
     bash deploy/install.sh
```

脚本会：装依赖到 conda 环境 → 构建前端 → 生成 `.env` → 写 systemd unit → 启动 → 探活。

- `USE_CONDA=1` 表示用 Miniforge 环境、不建 `.venv`；脚本会把
  `PA_INSTALL_USE_CONDA=1`、`PA_INSTALL_CONDA_PREFIX`、`PA_INSTALL_CONDA_ENV` 写进 `.env`，
  以后重跑 `install.sh` 不带参数也继续用同一个环境。
- `sudo` 会重置 `$HOME`，所以 `CONDA_PREFIX_DIR` 必须写**绝对路径**。
- 口令只走环境变量（落进 `.env`），**不要**写进 `config/configs.cfg`：那份文件里
  `mysql_pass` / `pg_pass` / `secret_key` 必须留空。

**3.1 `.env` 关键项**

| 变量 | 含义 |
|---|---|
| `PA_DB_MYSQL_HOST/PORT/USER/PASS/DB` | MySQL 连接 |
| `PA_AGENT_PG_HOST/PORT/USER/PASS/DB` | PG 连接（**前缀必须是 section 名 `AGENT`**，写成 `PA_PG_PASS` 不生效） |
| `PA_LLM_DEEPSEEK_API_KEY` / `PA_LLM_BASE_URL` / `PA_LLM_MODEL` | 模型网关 |
| `PA_APP_SECRET_KEY` | 会话签名密钥（首次安装自动生成，别改） |
| `PA_KB_EMBED_URL` | 嵌入服务地址，默认 `http://127.0.0.1:5110` |
| `PA_INSTALL_CONDA_*` | 记录安装用的 conda 环境 |

## 4. 初始化管理员

```bash
cd /opt/open-agent-harness
PYTHONPATH=. "$HOME/miniforge3/envs/oah/bin/python" deploy/seed_admin.py --password '「管理员密码」'
```

初始化后的数据：

| 表 | 内容 |
|---|---|
| `pa_roles` | `admin`（管理员，全部工具）、`default`（公共角色，公共工具） |
| `pa_users` | `admin` |
| `pa_user_roles` | admin → admin |

之后新建用户：不选角色 = 公共角色；不填密码 = `123456`（首次登录务必改）。

## 6. 文档知识库（可选）

上传 PDF / Word / Excel / PPT，切分后向量化存 PG（pgvector），对话时按需检索；扫描件走 OCR。

**6.1 装嵌入服务**（bge-m3，ONNX int8，CPU 即可）

```bash
# 单独 conda 环境，避免和主服务依赖打架
"$HOME/miniforge3/bin/conda" create -y -n kb-embed --override-channels -c conda-forge python=3.12
"$HOME/miniforge3/envs/kb-embed/bin/pip" install -r requirements-embed.txt

# 模型权重放 /var/lib/oah-embed/bge-m3-int8（model.onnx + tokenizer*.json + config.json）
sudo cp deploy/pa-kb-embed.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now pa-kb-embed

curl -s http://127.0.0.1:5110/health
# {"ok":true,"embedding_model":"BAAI/bge-m3","backend":"onnx","dim":1024}
```

**6.2 入库**

页面上传文件后进队列，后台 worker 解析 → 切分（350 字/重叠 60）→ 嵌入 → 写入 `data_kb_nodes`。
1 万字约 3~5 分钟；状态在「知识库 → 文档资料」看（排队中 → 索引中 → 可用）。

**6.3 排障**

| 现象 | 原因 / 处理 |
|---|---|
| `stats.docs` 有、`chunks=0` | 嵌入服务不可达 → `curl 127.0.0.1:5110/health` |
| 文档一直「索引中」 | 看 `journalctl -u open-agent-harness -n 50`，多为嵌入超时；单块 350 字是上限，别调大 |
| 检索不命中 | 先确认文档状态是「可用」，再看 scope（个人/共享）是否匹配 |

更多细节见 [`知识库部署说明.md`](知识库部署说明.md)。

## 7. MCP 接入（可选）

把别人的 MCP 服务（streamable_http）接成 agent 的工具。工具名规则：`mcp_<服务名>_<工具名>`。

**7.1 页面接入**（管理员）

「技能与工具 → MCP 服务 → 新增服务」填：

| 字段 | 说明 |
|---|---|
| 服务名 | 小写字母/数字/`-`/`_`，≤24 字符（决定工具名前缀） |
| 接入地址 | 对方的 `https://…/mcp` |
| 请求头 | 需要鉴权时填，每行一个：`Authorization: Bearer xxxxx` |

保存 → 点「测试」看到工具清单 → 进「工具管理」把工具设**公共**或分配给角色 →
最多 30 秒生效（多 worker 的工具缓存 TTL）。

**7.2 仓库自带的示例服务**（查天气，用来验证链路）

```bash
sudo cp deploy/pa-mcp-weather.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now pa-mcp-weather
curl -s http://127.0.0.1:5120/health      # {"ok":true,...,"tools":["get_weather"]}
```

然后在页面加一条：服务名 `weather`，地址 `http://127.0.0.1:5120/mcp`，请求头留空。

**7.3 客户端链路自检**（离线，不依赖外网/数据库）

```bash
PYTHONPATH=. "$HOME/miniforge3/envs/oah/bin/python" test/mcp_weather/check.py
# 期望 6 个 ✓，最后一行：MCP 链路端到端：全部通过
```

**7.4 排障**

| 现象 | 处理 |
|---|---|
| 页面显示「未连接」 | 点「测试」，行尾 ⚠ 的 tooltip 有具体错误 |
| 401 / 403 | 请求头格式或 Token 过期 |
| timeout | 在服务器上 `curl -H 'Accept: application/json, text/event-stream' <url>` 验可达 |
| 已连接但模型说没这个工具 | 工具未授权给角色，或还没到 30 秒缓存过期 |

MCP 只支持 **streamable_http**（不做 stdio，不开放"在服务器上起进程"的配置）。

## 8. 验收清单

```bash
B=http://127.0.0.1:5002/open-agent-harness
curl -s $B/api/health                       # {"ok":true,"db":"ok","redis":"ok"}
systemctl is-active open-agent-harness      # active
journalctl -u open-agent-harness -n 30 | grep -cE "Traceback|ERROR"   # 期望 0
```

- [ ] 登录页能打开，admin 能进
- [ ] 发一轮对话有流式输出
- [ ] 「技能与工具」能看到工具清单（`ask_user`、`sandbox_shell` 等）

- [ ] MCP 服务页「测试」能列出工具（若接了）
- [ ] 改掉默认口令，`config/configs.cfg` 里没有明文口令

## 9. 日常运维

```bash
systemctl status open-agent-harness        # 状态
systemctl restart open-agent-harness       # 重启（绑定要 20~25 秒，别立刻 curl）
journalctl -u open-agent-harness -f        # 日志
```

**升级**：本地改完用 `git archive` 覆盖到服务器 → 有依赖变更就重装 → 重启 → 跑 §8 验收。
前端有改动时要在服务器上 `cd frontend && npm run build`（`dist/` 是构建产物，不在仓库里）。

**备份**：

```bash
mysqldump -u agent -p open_agent_harness > oah-$(date +%F).sql
sudo -u postgres pg_dump -Fc kb > kb-$(date +%F).dump
```

## 10. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 启动即退出 | PostgreSQL 连不上（§1 里说了必装）；看 `journalctl -u open-agent-harness -n 50` |
| `no password supplied` / `PoolTimeout` | 手动跑脚本时没加载 `.env`：先 `set -a && . ./.env && set +a` |
| 端口被占用 / 起不来 | `ss -lntp \| grep 5002`；确认没有旧进程 |
| 页面 404 | 路径要带 `/open-agent-harness/`（部署前缀） |
| 对话报模型错误 | 检查 `.env` 的 `PA_LLM_*`；网关要 OpenAI 兼容 |
| Redis 连接失败 | 属降级：限流/权限缓存失效，功能仍可用；生产建议装上 |
| 知识库任务卡住 | 嵌入服务挂了或超时；`systemctl restart pa-kb-embed` 后重新点「重建」 |
