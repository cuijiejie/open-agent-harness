# 部署说明

约 20 分钟，命令可以直接复制。装完你会得到一个能登录、能对话的系统，以及 **1 个管理员账号 + 4 个角色**。

---

## 0. 准备什么

| 项 | 要求 | 必需 |
|---|---|---|
| 系统 | Ubuntu 22.04（其他 Linux 也行） | ✅ |
| Python | **3.12**（安装脚本会检查） | ✅ |
| Node.js | 18+（前端要现场构建） | ✅ |
| MySQL | 8.0 | ✅ |
| 模型 | 任何 OpenAI 协议的 API Key | ✅ |
| PostgreSQL | 14+，让对话上下文不丢 | 建议 |
| Redis | 6+，权限缓存/限流 | 建议 |
| Docker + OpenShell | 让模型能读文件、跑命令 | 可选 |

没有 Python 3.12：`sudo apt install -y python3.12 python3.12-venv`
没有 Node 18+：`curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt install -y nodejs`

## 1. 建库（一次性）

```sql
CREATE DATABASE open_agent_harness
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'agent'@'%' IDENTIFIED BY '你的数据库密码';
GRANT ALL PRIVILEGES ON open_agent_harness.* TO 'agent'@'%';
FLUSH PRIVILEGES;
```

**表不用建**，服务启动时自动建。

---

## 2. 一键安装

```bash
git clone https://github.com/cuijiejie/open-agent-harness.git /opt/open-agent-harness
cd /opt/open-agent-harness

sudo PA_DB_MYSQL_PASS='你的数据库密码' \
     PA_LLM_DEEPSEEK_API_KEY='sk-你的模型key' \
     bash deploy/install.sh
```

脚本做的事：建虚拟环境 → 装依赖 → 构建前端 → 生成 `.env` → 装 systemd → 启动 → 探活。
**幂等**，重复执行就是升级。

换目录/端口：`sudo APP_DIR=/srv/agent PORT=8080 ... bash deploy/install.sh`

> 依赖从 pypi 下载慢就先 `export PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/`；
> npm 慢就 `npm config set registry https://registry.npmmirror.com`。

## 3. 建管理员（必做，只做一次）

```bash
cd /opt/open-agent-harness
PYTHONPATH=. .venv/bin/python deploy/seed_admin.py
```

创建账号 **`admin` / 密码 `admin`**，挂到「管理员」角色。已经存在就不覆盖。

常用变体：

```bash
... deploy/seed_admin.py --password 'N3wPass!'     # 直接设成别的密码
... deploy/seed_admin.py --force-reset             # 已有密码也重置
... deploy/seed_admin.py --username zhangsan       # 换个账号名
```

## 4. 打开验证

浏览器访问 `http://<服务器IP>:5001/open-agent-harness/`，用 `admin / admin` 登录。

三条命令也可以确认：

```bash
systemctl is-active open-agent-harness                                   # active
curl -s http://127.0.0.1:5001/open-agent-harness/api/health              # {"ok":true,"db":"ok",...}
grep 'RBAC 表就绪' /opt/open-agent-harness/logs/app.log | tail -1        # 表建好了
```

**登录后第一件事**：点左下角钥匙图标，把 `admin` 的密码改掉。

## 5. 部署完库里有什么（初始化数据）

只有这些，没有任何演示数据。

**角色（启动时自动写入）**

| 显示名 | 编码 | 内置 | 工具 |
|---|---|---|---|
| 管理员 | `admin` | ✅ 不可删 | `*`（全部） |
| 公共角色 | `default` | ✅ 不可删 | 公共工具（见下） |
| 操作员 | `operator` | ❌ 可删 | `ask_user`、`sandbox_shell` |
| 查看者 | `viewer` | ❌ 可删 | `ask_user` |

**公共工具**（`pa_tools.always_on`）：`ask_user`、`remember_fact`、`remember_preference`、
`forget_fact`、`forget_preference`、`sandbox_shell`。

**用户**

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `admin`（bcrypt 存库，无明文） | 管理员 |

之后新建的用户：**不选角色 → 公共角色**，**不填密码 → `123456`**。

核对命令：

```bash
cd /opt/open-agent-harness && set -a && . ./.env && set +a
PYTHONPATH=. .venv/bin/python -c "
from src.infra.RbacService import rbac
for r in rbac.list_roles():
    print('%-6s %-9s 内置=%-5s 工具=%s' % (r['role_name'], r['role_code'], r['is_builtin'], r['tools']))
for u in rbac.page_users('', '', 1, 50)['users']:
    print('  %-10s 角色=%s 状态=%s' % (u['username'], u['roles'], u['status']))
"
```

## 6. 日常三件事

**加人**：页面「系统设置 → 用户管理 → 新增用户」。
接口版（`roles` 不传=公共角色，`password` 不传=123456）：

```bash
BASE=http://127.0.0.1:5001/open-agent-harness
curl -c ck -o /dev/null -X POST -d 'username=admin&password=admin' "$BASE/login"
curl -b ck -X POST "$BASE/api/users" -H 'Content-Type: application/json' \
  -d '{"username":"alice","display_name":"Alice","roles":["operator"],"password":"InitPass1"}'
```

**改密码**：用户自己点左下角钥匙图标（旧密码+新密码）；
管理员给别人重置：`POST /api/users/{账号}/password`（页面在「用户管理 → 重置密码」）。

**调权限**：页面「系统设置 → 角色管理」勾工具。
角色保存后立即生效，不用重启。

## 7. 可选组件（用到了再配）

改 `.env` 后 `sudo systemctl restart open-agent-harness`。

**PostgreSQL**（对话上下文持久化，不配则刷新后上下文丢）

```ini
PA_AGENT_PG_HOST=127.0.0.1
PA_AGENT_PG_DB=agent_state
PA_AGENT_PG_USER=postgres
PA_AGENT_PG_PASS=PG密码
```

**Redis**（权限缓存 / 限流 / 防重复提交）

```ini
PA_REDIS_REDIS_HOST=127.0.0.1
PA_REDIS_REDIS_PASSWORD=Redis密码
PA_REDIS_REDIS_CLUSTER=false      # 集群填 true
```

**沙箱**（模型能跑命令、读写文件、出报表）

```ini
# config/configs.cfg
[agent]
openshell_enabled = true
openshell_bin = /snap/bin/openshell
openshell_image = pa-sandbox:1.3
```

不开沙箱也能用，只是没有执行类工具。

## 8. 升级

```bash
cd /opt/open-agent-harness
git pull
sudo PA_DB_MYSQL_PASS='你的数据库密码' PA_LLM_DEEPSEEK_API_KEY='sk-xxx' bash deploy/install.sh
bash deploy/verify.sh          # 验收：服务/健康/前端/单测/日志
```

> ⚠️ `frontend/dist` **不在 git 里**。只改后端时 `git pull` 不影响前端；
> 改过前端必须重新 `cd frontend && npm ci && npm run build`。
> 页面报 `{"error":"前端未构建: index.html"}` 就是 dist 没了。

## 9. 出问题先看这几条

| 现象 | 原因 / 处理 |
|---|---|
| 服务起来又挂 | `.env` 路径不对、端口被占：`journalctl -u open-agent-harness -n 50` |
| 页面白屏 / 502 | dist 没构建：`ls frontend/dist/index.html` |
| 登录提示「用户名或密码错误」 | 账号不存在、密码错、账号被停用；管理员重置密码 |
| 登录提示「该账号尚未设置密码」 | 老版本升级来的账号，管理员重置一次 |
| 发消息不出字 | 模型 key / base_url 错：`grep -i 'llm\|401' logs/app.log` |
| 刷新后上下文丢了 | PG 没配或连不上 |
| 工具在但模型不调用 | 该角色的工具没勾上 → 角色管理勾选后重新登录 |

日志：`logs/app.log`（应用）、`journalctl -u open-agent-harness -f`（服务层）。

## 附：常改的配置

配置分两处，别放错：

| 位置 | 放什么 |
|---|---|
| `config/configs.cfg`（入库） | 地址、端口、模型名、开关、阈值 |
| `.env`（不入库，权限 600） | **所有口令和密钥** |

变量名规则 `PA_<段>_<键>`（大写），环境变量优先于配置文件。

| 想改 | 改哪里 |
|---|---|
| 数据库连接 | `config/configs.cfg` `[db]` 或 `PA_DB_MYSQL_*` |
| 模型/网关 | `[llm] deepseek_model` / `deepseek_base_url` |
| 端口 | 单元文件 `ExecStart --port`，或 `PORT=8080 bash deploy/install.sh` |
| 默认角色 | `[app] default_role`（默认 `default` = 公共角色） |
| 报错显示细节 | `[app] error_detail`（默认 false） |

**上生产前**：`admin` 默认密码已改、老账号都重置过密码、`.env` 权限 600、
数据库账号只授权本库、前面放 Nginx（SSE 要 `proxy_buffering off`）。
