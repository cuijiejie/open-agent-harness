# 部署说明

本文是仓库里**唯一**的部署文档：从零到能对话，按顺序做即可。
预计 20~30 分钟（不含下载依赖）。

---

## 0. 这个东西是什么

一个以对话为入口、以工具为手脚、以沙箱为工作台的智能体平台：

- **对话**：SSE 流式输出，支持中断恢复（LangGraph checkpointer）
- **工具**：内置工具 + 插件工具 + 外部 MCP 服务，**按角色装配**（没权限的工具不进模型清单）
- **沙箱**：每个用户一个隔离容器，能在里面读写文件、跑 Python、生成报表（可选，见 §6）
- **可观测**：每一步工具调用都有轨迹，管理操作另有审计

技术栈：Flask 3 + LangGraph 1 + deepagents + Vue 3 + MySQL + PostgreSQL + Redis（可选）。

## 1. 前置条件

| 组件 | 版本 | 必需 | 说明 |
|---|---|---|---|
| Python | 3.12 | ✅ | 3.11 也能跑，但依赖按 3.12 锁的 |
| Node.js | 18+ | ✅ | 只用于构建前端；也可以直接用别人构建好的 `frontend/dist` |
| MySQL | 8.0+ | ✅ | 业务库：会话、消息、RBAC、工具元数据、审计 |
| PostgreSQL | 14+ | 🟡 建议 | LangGraph 的对话状态（不配也能跑，但刷新/重启后上下文丢失） |
| Redis | 6+ | 🟡 建议 | 权限快照、列表缓存、每用户限流；不配就是每次查库，功能正常但更慢 |
| OpenShell | 最新 | 🟡 可选 | 沙箱执行环境；不装就把 `openshell_enabled=false`，其余功能照常 |
| 操作系统 | Linux | ✅ | systemd 部署；Windows/macOS 可本地开发 |

## 4. 建库

### 4.1 MySQL（业务库）

```sql
CREATE DATABASE open_agent_harness
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'agent'@'%' IDENTIFIED BY '<你的密码>';
GRANT ALL PRIVILEGES ON open_agent_harness.* TO 'agent'@'%';
FLUSH PRIVILEGES;
```

**表不用手动建**：应用启动后首次访问会自动建表（`CREATE TABLE IF NOT EXISTS`），
RBAC 会顺带写入内置角色（`admin` 管理员、`default` 公用角色）。

### 4.2 PostgreSQL（对话状态，可选）

```sql
CREATE DATABASE agent_state;
```

checkpointer 的表也由程序自动建（`src/infra/CheckpointerManager.py`）。
如果连不上 PG，服务仍能启动，只是没有跨会话上下文。

## 5. 配置

只有**一个**配置文件：`config/configs.cfg`（进仓库）。

分工很明确：

| 放哪儿 | 放什么 |
|---|---|
| `config/configs.cfg` | 非敏感配置：库地址、端口、模型名、网关、开关、阈值 |
| 环境变量 `PA_*=xxx` | **所有口令与密钥**：数据库密码、模型 key、PG 密码、session 密钥 |

必填的环境变量（不填则对应功能不可用）：

```bash
export PA_DB_MYSQL_PASS=xxx                              # MySQL 密码
export PA_LLM_DEEPSEEK_API_KEY=sk-xxx                    # 模型密钥
export PA_APP_SECRET_KEY=$(python -c "import secrets;print(secrets.token_hex(32))")
# 可选
export PA_PG_PASS=xxx                                    # PostgreSQL 密码（不配则用内存 checkpointer）
export PA_REDIS_REDIS_PASSWORD=xxx                       # Redis 密码
export PA_APP_LOGIN_PASSWORD=xxx                         # 登录口令（不设=免密）
```

要改非敏感项，直接编辑 `config/configs.cfg`；也可以临时用环境变量覆盖同名项
（规则 `PA_<SECTION>_<KEY>`，如 `PA_DB_MYSQL_HOST`）。
优先级：环境变量 > 配置文件 > 代码默认值。

配置文件路径可用 `PA_CONFIG_FILE=/etc/agent/configs.cfg` 指到别处（容器化常用）。
不再区分 dev / uat / pro 目录：同一份配置，不同环境靠注入不同环境变量区分。

## 7. 启动

### 7.1 开发 / 试跑

```bash
source .venv/bin/activate
python AgentApp.py                      # 监听 0.0.0.0:5001
```

打开 `http://<主机>:5001/open-agent-harness/`。
开发环境可以直接用免密登录：`http://<主机>:5001/open-agent-harness/test-login`，
输入任意用户名即可（**生产必须把 `[app] test_login_enabled` 设为 false**）。

### 7.2 生产（systemd + gunicorn）

```bash
cp deploy/open-agent-harness.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now open-agent-harness
systemctl status open-agent-harness
```

单元文件默认路径是 `/opt/open-agent-harness`，换了目录要同步改 `WorkingDirectory`、`ExecStart`。

关键启动参数（**别随意改**）：

```
--workers 6 --worker-class gthread --threads 4   # 24 个并发槽
--timeout 1300                                    # 必须大于单轮上限 turn_max_seconds
--config gun_warm.py                              # 每个 worker 启动后预热 MCP 工具清单
```

> 为什么必须是 gthread：默认 sync worker 会忽略 `--threads`，6 进程实际只有 6 并发，
> 而对话是 SSE 长连接 + 阻塞式外部调用，并发一高就排队。

### 7.3 Nginx 反向代理（如果放在 80/443 后面）

```nginx
location /open-agent-harness/ {
    proxy_pass http://127.0.0.1:5001;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;          # SSE 必须关，否则前端“点了没反应，10 秒后一次性出来”
    proxy_read_timeout 300s;      # 默认 60s 会切断长任务
}
```

## 9. 可选组件

### 9.1 沙箱（OpenShell）

```ini
[agent]
openshell_enabled = true
openshell_bin = /snap/bin/openshell
openshell_policy = config/sandbox-policy.yaml
openshell_image = pa-sandbox:1.3
```

- 镜像自建：`docker/pa-sandbox.Dockerfile`（预装 pandas / openpyxl / matplotlib / python-docx）
- 每个用户一个容器，**登录时后台创建**，闲置 7 天只 `stop`（文件保留），用户不存在才删
- `config/sandbox-policy.yaml` 默认**拒绝所有出站**；要访问内网库/外部 API 得显式放行

不启用沙箱时：`sandbox_shell` 工具会明确报错，对话、插件工具、记忆都正常。

### 9.2 MCP 服务

```ini
[mcp]
enabled = true
servers = my_tools|python|-m my_mcp_server|API_KEY=xxx
```

MCP 服务只能管理员在配置里声明（用户不可自装），跑在宿主机上。

### 9.3 登录与口令

平台自带本地登录，不依赖 CAS / OAuth：

| 配置 | 作用 |
|---|---|
| `[app] login_password` | 留空 = 免密（内网演示）；填了则所有用户共用这一个口令 |
| `[app] test_login_enabled` | `/test-login?username=xxx` 免密直登，给脚本冒烟用；**对外开放时必须 false** |
| `[app] secret_key` | session 签名密钥，多 worker 必须一致，否则登录态随机失效 |

要接自己的 SSO：改 `src/infra/utils/AuthUtil.py` 的 `_authenticate()`，
或在网关层做认证后把用户名写进 session（`USERNAME` 键），其余代码不用动。

## 10. 日常运维

### 10.1 日志

```
logs/app.log                应用日志（按天切分，保留 365 天）
open-agent-harness.log   gunicorn 访问/错误日志
```

### 10.2 定时维护（4 个独立 timer，一个任务一件事）

```bash
bash deploy/install-maintenance-timers.sh
systemctl list-timers 'pa-*'
```

| timer | 时间(UTC) | 做什么 |
|---|---|---|
| `pa-logs` | 03:00 | 日志切分 + 删 365 天前 |
| `pa-artifacts` | 03:10 | 删 90 天没动过的交付物副本（沙箱原件不动） |
| `pa-sandbox-idle` | 03:20 | 闲置 7 天 → `sandbox stop`（只停不删） |
| `pa-sandbox-orphan` | 03:30 | 用户已不存在 + 3 天 → `sandbox delete` |

单独预演：`python -m src.infra.Maintenance sandbox-idle --dry-run`

### 10.3 升级

```bash
git pull
source .venv/bin/activate && pip install -r requirements.txt
cd frontend && npm ci && npm run build && cd ..
systemctl restart open-agent-harness
bash deploy/verify.sh      # 发版后验收
```

## 11. 故障排查

| 现象 | 先看什么 |
|---|---|
| 启动失败，报找不到配置 | `config/configs.cfg` 是否存在；或设 `PA_CONFIG_FILE` |
| 健康检查 500 | `logs/app.log` 里的第一条 ERROR，通常是 MySQL 连不上 |
| 页面打开是空白 | 前端没构建：`frontend/dist/index.html` 存在吗 |
| 能登录但对话不出字 | 模型 key / base_url 是否正确；看日志里 LLM 相关报错 |
| 刷新后上下文丢失 | PostgreSQL 没配或连不上（checkpointer 起不来） |
| 工具没出现在界面上 | 插件 `manifest.json` 是否被扫描到；`logs` 里搜 `[plugins]` |
| 工具在界面但模型不调用 | 该角色没分配这个工具（RBAC → 角色 → 工具） |
| 权限改了不生效 | 权限快照有 300 秒 TTL；正常情况下改角色会主动清缓存 |
| 沙箱命令超时 | `openshell sandbox list` 看容器状态；容器太多会拖慢，跑一次维护任务清理 |

## 12. 安全须知（上生产前必做）

1. `[app] test_login_enabled` 设为 **false**，否则任何人输入用户名即可登录
2. `[app] secret_key` 换成随机值，且**不要提交进仓库**
3. 配置里的所有口令/密钥走环境变量或独立配置文件（`.gitignore` 已忽略 `configs.cfg`、`.env`）
4. `openshell_enabled=true` 时，`config/sandbox-policy.yaml` 默认拒绝出站，按需最小放行
5. 建议放在内网或加认证网关；平台自身的 RBAC 管的是**工具权限**，不是网络准入
