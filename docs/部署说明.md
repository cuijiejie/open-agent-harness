# 部署说明

> 服务端已从 Flask 迁到 FastAPI + 全链路异步，本文是**部署视角**；
> 改造细节（阶段、契约、踩坑、回滚）见 [`迁移说明-Flask到FastAPI.md`](迁移说明-Flask到FastAPI.md)。

从零到能对话。**照着敲就行**，全程 20~30 分钟（主要是下依赖）。

- 只想先跑起来看看 → 直接看 [§2 一键部署](#2-一键部署推荐)
- 想把每一步都搞清楚 → 看 [§3 手动部署](#3-手动部署逐步骤)
- 卡住了 → 看 [§9 故障排查](#9-故障排查)

## 1. 先确认你要装什么

| 组件 | 必需 | 不装会怎样 |
|---|---|---|
| Python 3.11+（推荐 3.12） | ✅ | 跑不起来 |
| MySQL 8.0 | ✅ | 跑不起来（会话、账号、权限、审计都在这里） |
| Node.js 18+ | ✅ 仅构建期 | 前端没得构建（也可以直接用仓库里的 `frontend/dist`） |
| PostgreSQL 14+ | 🟡 建议 | 能跑，但**刷新/重启后对话上下文丢失** |
| Redis 6+ | 🟡 建议 | 能跑，权限每次查库、限流失效，并发高时变慢 |
| OpenShell + Docker | 🟡 可选 | 能跑，但**不能读文件/跑命令/生成报表**（只剩聊天和纯计算类工具） |

一句话：**MySQL + 模型 key 是硬门槛，其余都能后补。**

## 2. 一键部署（推荐）

```bash
git clone <仓库地址> /tmp/oah && cd /tmp/oah

# 先把数据库建好（只需一次，密码自己定）
mysql -uroot -p -e "
CREATE DATABASE open_agent_harness DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'agent'@'%' IDENTIFIED BY '你的数据库密码';
GRANT ALL PRIVILEGES ON open_agent_harness.* TO 'agent'@'%';
FLUSH PRIVILEGES;"

# 走一键安装（会自动建 venv、装依赖、构建前端、生成 .env、装 systemd、探活）
sudo PA_DB_MYSQL_PASS='你的数据库密码' \
     PA_LLM_DEEPSEEK_API_KEY='sk-你的模型key' \
     bash deploy/install.sh
```

装完打开 `http://<服务器IP>:5001/open-agent-harness/` 就能登录。

> **还差一步**：脚本不会自动建管理员账号。首次部署请按 [3.7 创建首个管理员](#37-创建首个管理员首次部署必做) 做一次（建用户 + 挂 `admin` 角色），然后**立刻**设置 `login_password` 或接入 CAS。

**自定义路径与端口：**

```bash
sudo APP_DIR=/srv/agent PORT=8080 \
     PA_DB_MYSQL_PASS=xxx PA_LLM_DEEPSEEK_API_KEY=sk-xxx \
     bash deploy/install.sh
```

> 脚本是**幂等**的：再跑一次就是升级（重装依赖 → 重建前端 → 重启服务 → 探活）。
> 已有的 `.env` 不会被覆盖。

## 3. 手动部署（逐步骤）

每步后面都有「怎么确认这一步成了」。

### 3.1 放代码

```bash
sudo mkdir -p /opt/open-agent-harness
sudo cp -a . /opt/open-agent-harness/     # 或 git clone 到该目录
cd /opt/open-agent-harness
```

✅ 确认：`ls` 能看到 `requirements.txt`、`config/`、`frontend/`

### 3.2 Python 环境

```bash
python3.12 -m venv .venv     # 只有 3.11/3.13 也行：换成对应命令
source .venv/bin/activate
pip install -U pip
pip install -r requirements.txt
```

✅ 确认：`python -c "import fastapi, uvicorn, langgraph, deepagents, psycopg, asyncmy; print('ok')"`

> **装依赖慢 / 超时**（pypi.org 在国内常抽风）：换源即可，一键脚本和手动命令都认这两个变量：
>
> ```bash
> export PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
> export PIP_TRUSTED_HOST=mirrors.aliyun.com
> ```
>
> npm 同理：`npm config set registry https://registry.npmmirror.com`

> `deepagents` / `langgraph` / `langgraph-checkpoint-postgres` 三个版本互相咬合，
> 按 `requirements.txt` 装，别单独升其中一个。

### 3.3 建库

```sql
CREATE DATABASE open_agent_harness
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'agent'@'%' IDENTIFIED BY '你的数据库密码';
GRANT ALL PRIVILEGES ON open_agent_harness.* TO 'agent'@'%';
FLUSH PRIVILEGES;
```

**表不用建**：服务启动时自动建（`src/infra/db/bootstrap.py`），
其余表首次用到时自建。不需要跑任何初始化脚本。

✅ 确认：`mysql -uagent -p open_agent_harness -e "select 1"`

### 3.4 配置密钥

配置文件是 `config/configs.cfg`（已入库，只放**非敏感项**）；
**所有口令/密钥都走环境变量**，写在 `.env` 里由 systemd 注入：

```bash
cat > /opt/open-agent-harness/.env <<'EOF'
# 必填
PA_DB_MYSQL_PASS=你的数据库密码
PA_LLM_DEEPSEEK_API_KEY=sk-你的模型key
PA_APP_SECRET_KEY=用下面的命令生成

# 选填
PA_PG_HOST=127.0.0.1
PA_PG_PASS=PG密码
PA_REDIS_REDIS_PASSWORD=Redis密码
PA_APP_LOGIN_PASSWORD=登录口令（不填=免密）
EOF
chmod 600 /opt/open-agent-harness/.env

# 生成 session 密钥
python3 -c "import secrets;print(secrets.token_hex(32))"
```

✅ 确认：`grep -c '^PA_' .env` 至少 3 个

### 3.5 构建前端

```bash
cd frontend
npm ci
npm run build      # 产物 frontend/dist
cd ..
```

✅ 确认：`ls frontend/dist/index.html`

### 3.6 启动

**开发/试跑：**

```bash
source .venv/bin/activate
PYTHONPATH=. python -m uvicorn src.app_fastapi:app --host 0.0.0.0 --port 5001 --workers 4
```

**生产（systemd）：**

```bash
sudo cp deploy/open-agent-harness.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now open-agent-harness
```

✅ 确认：

```bash
systemctl is-active open-agent-harness       # active
grep '数据库自检完成' logs/app.log | tail -1  # 数据库自检完成：2 张表 [...]
```

> 装到别的目录要改单元文件里的 3 处路径（`WorkingDirectory`、`Documentation`、`ExecStart`），
> 或用一键脚本自动替换。

### 3.7 创建首个管理员（首次部署必做）

**角色不用你建。** 首次启动时 `admin` 角色已随预置角色写进 `pa_roles`
（`tools = ["*"]`、`is_admin = 1`、内置不可删）。你只需要建**用户**并把用户挂到这个角色上。

> 系统**不会**在启动时代码里自动建管理员账号 —— 否则每次部署都会凭空多出一个
> 免密的管理员入口。这一步请按下面的方式显式做一次。

**方式一：直接写库（推荐，不需要已有管理员）**

```bash
cd /opt/open-agent-harness          # 换成你的 APP_DIR
PYTHONPATH=. .venv/bin/python - <<'PY'
import pymysql
from config.Configs import cfg

USER = "admin"                      # 想用别的登录名就改这里
cur = pymysql.connect(host=cfg.mysqlHost, port=int(cfg.mysqlPort), user=cfg.mysqlUser,
                      password=cfg.mysqlPass, database=cfg.mysqlDB,
                      charset="utf8mb4", autocommit=True).cursor()
# 1) 用户（已存在则只确保 active）
cur.execute("INSERT INTO pa_users (username, display_name, status) VALUES (%s,%s,'active') "
            "ON DUPLICATE KEY UPDATE status='active'", (USER, "管理员"))
# 2) 关联内置 admin 角色（工具 *、is_admin=1 已由预置角色提供）
cur.execute("INSERT IGNORE INTO pa_user_roles (username, role_code) VALUES (%s,'admin')", (USER,))
print("done:", USER, "-> admin")
PY
```

幂等，重复执行不报错；也不会覆盖你之后在「用户管理」里做的调整。

**方式二：已经有管理员时用接口**

```bash
# 以现有管理员身份登录（浏览器里拿到 session cookie）
curl -b "session=<cookie>" -X POST http://127.0.0.1:5001/open-agent-harness/api/users \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","display_name":"管理员","roles":["admin"]}'
```

**校验**

```bash
# 用该账号登录后调 /api/rbac/me，期望 is_admin=true、tools="*"
curl -b "session=<cookie>" http://127.0.0.1:5001/open-agent-harness/api/rbac/me
```

> ⚠️ **安全提醒**：本系统默认「输入用户名即可登录」（`[app] login_password` 为空时不校验口令）。
> 建完管理员后**立刻**做两件事：
> 1. 设 `[app] login_password`（或接入 CAS）；
> 2. 确认 `[app] test_login_enabled = false`（免密直登入口关闭）。
> 否则任何人都能在登录页输入 `admin` 直接进来。

## 4. 验证（6 项，全绿才算成）

```bash
# ① 服务活着
systemctl is-active open-agent-harness

# ② 页面能出（200 或 302 都算正常，302=未登录跳登录页）
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5001/open-agent-harness/

# ③ 登录页能打开
curl -s http://127.0.0.1:5001/open-agent-harness/login | grep -o '<title>[^<]*</title>'

# ④ 数据库通了（有这行说明表和连接都正常）
grep '数据库自检完成' logs/app.log | tail -1

# ⑤ 浏览器能对话
#    打开 http://<IP>:5001/open-agent-harness/ → 登录 → 发「你好」

# ⑥ 管理员身份正确（按 3.7 建的账号登录后）
curl -b "session=<cookie>" http://127.0.0.1:5001/open-agent-harness/api/rbac/me
#    期望 "is_admin": true 且 "tools": "*"
```

第 ⑤ 步第一次会比之后慢几秒（要建 agent、连 MCP、读技能目录），属正常。

## 5. 配置速查

两个地方，分工不重叠：

| 位置 | 放什么 | 例子 |
|---|---|---|
| `config/configs.cfg`（入库） | 地址、端口、模型名、开关、阈值 | `mysql_host`、`deepseek_model`、`openshell_enabled` |
| `.env` / 环境变量（不入库） | **所有口令与密钥** | `PA_DB_MYSQL_PASS`、`PA_APP_SECRET_KEY` |

变量名规则：`PA_<SECTION>_<KEY>`（大写）。优先级：**环境变量 > 配置文件 > 代码默认值**。

### 5.1 最常改的几个

| 想改什么 | 改哪里 | 怎么改 |
|---|---|---|
| 数据库地址/库名 | `config/configs.cfg` `[db]` | 直接改，或 `PA_DB_MYSQL_HOST` 覆盖 |
| 用别的模型/网关 | `[llm] deepseek_model / deepseek_base_url` | 任何 OpenAI 协议网关都行 |
| 端口 | systemd 单元 `--bind` | 或 `PORT=8080 bash deploy/install.sh` |
| 登录口令 | `.env` `PA_APP_LOGIN_PASSWORD` | 留空=免密；填了所有人共用这个口令 |
| 免密直登入口 | `[app] test_login_enabled` | **对外开放必须 false** |
| 报错要不要显示细节 | `[app] error_detail` | 默认 false（只给通用提示） |
| 开沙箱 | `[agent] openshell_enabled` | 见 §6.1 |

## 6. 可选组件

### 6.1 沙箱（让模型能读文件、跑命令、出报表）

```ini
[agent]
openshell_enabled = true
openshell_bin = /snap/bin/openshell
openshell_image = pa-sandbox:1.3
```

```bash
# 镜像自建（预装 pandas / openpyxl / matplotlib / python-docx）
sudo docker build -t pa-sandbox:1.3 -f docker/pa-sandbox.Dockerfile .
```

- 每个用户一个容器，**登录时后台创建**，闲置 7 天只 `stop`（文件全留），用户被删才 `delete`
- `config/sandbox-policy.yaml` 默认**拒绝所有出站**，要访问外部 API/内网库需显式放行
- 不开沙箱时 `sandbox_shell` 会明确报错，对话与插件工具照常

### 6.2 PostgreSQL（对话上下文持久化）

```sql
CREATE DATABASE agent_state;
```

`.env` 里填 `PA_PG_HOST / PA_PG_PASS`，表由程序自建。
连不上会自动降级为内存 checkpointer（日志有 ERROR），**不会导致起不来**。

### 6.3 Redis

`.env` 填 `PA_REDIS_REDIS_HOST / PA_REDIS_REDIS_PASSWORD / PA_REDIS_REDIS_DB`。
不配也能跑，只是权限每次查库。

### 6.4 MCP 服务

```ini
[mcp]
enabled = true
servers = my_tools|python|-m my_mcp_server|API_KEY=xxx
```

只有管理员能在配置里声明，跑在宿主机上，用户不可自装。

## 7. 设管理员

**第一个登录的人不会自动是管理员**（避免开放注册即提权）。给某个账号开管理员：

```sql
-- 角色 admin 是种子角色（is_admin=1, tools=*），无需新建
INSERT IGNORE INTO pa_users (username, display_name) VALUES ('alice', 'Alice');
INSERT IGNORE INTO pa_user_roles (username, role_code) VALUES ('alice', 'admin');
```

```bash
# 清权限缓存，6 个 worker 立刻生效（否则最多等 5 分钟）
.venv/bin/python -c "
import sys; sys.path.insert(0,'.')
from src.infra.RbacService import rbac
rbac.invalidate('alice'); print(rbac.permissions('alice'))"
```

✅ 确认：登录后左下角显示「管理员」，侧栏出现「系统设置」。

## 8. 放在 Nginx 后面

```nginx
location /open-agent-harness/ {
    proxy_pass http://127.0.0.1:5001;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_buffering off;        # SSE 必须关，否则"点了没反应，10 秒后一次性出来"
    proxy_read_timeout 300s;    # 默认 60s 会掐断长任务
    client_max_body_size 50m;   # 附件上传
}
```

## 9. 故障排查

| 现象 | 大概率原因 | 怎么查 |
|---|---|---|
| 服务起不来，`status` 一直 restart | `.env` 路径不对 / 端口被占 | `journalctl -u open-agent-harness -n 50`；`ss -lntp \| grep 5001` |
| 页面 502 / 空白 | 前端没构建 | `ls frontend/dist/index.html` |
| 页面能开，登录后白屏 | 静态资源 404 | 浏览器 F12 → Network 看 `assets/*.js` 状态码 |
| 登录后提示「服务暂时不可用」 | MySQL 连不上 | `grep ERROR logs/app.log \| tail -5` |
| 登录时提示 username/password 错误 | 设了 `PA_APP_LOGIN_PASSWORD` 但没输对 | `.env` 里对着看；或临时注释掉 |
| 发消息一直不出字 | 模型 key / base_url 错 | 日志里搜 `LLM` / `401` / `Unauthorized` |
| 报 `table doesn't exist` | 启动时建表失败（数据库权限不足） | 日志搜「数据库自检失败」；给账号补 `CREATE` 权限 |
| 刷新后上下文丢了 | PostgreSQL 没配或连不上 | 日志搜「降级为内存 checkpointer」 |
| 工具在界面但模型不调用 | 该角色没分配这个工具 | 系统设置 → 角色 → 勾选工具 → 重新登录 |
| 改完权限不生效 | 权限缓存 300 秒 TTL | 正常保存会自动清；手工清见 §7 |
| 沙箱命令超时 | 容器太多/没起 | `openshell sandbox list`；跑一次维护任务 |

日志位置：

```
logs/app.log                应用日志（按天切分）
uvicorn 访问/错误           同上（journalctl 里也有一份）
journalctl -u open-agent-harness -f   服务层（启动失败看这里）
```

## 10. 日常运维

### 10.1 升级

```bash
cd /opt/open-agent-harness
git pull
sudo PA_DB_MYSQL_PASS=x PA_LLM_DEEPSEEK_API_KEY=y bash deploy/install.sh   # 幂等，等于升级
```

或手动：

```bash
source .venv/bin/activate && pip install -r requirements.txt
cd frontend && npm ci && npm run build && cd ..
sudo systemctl restart open-agent-harness
bash deploy/verify.sh
```

### 10.2 定时维护（4 个独立 timer，一个任务一件事）

```bash
sudo bash deploy/install-maintenance-timers.sh
systemctl list-timers 'pa-*'
```

| timer | 时间(UTC) | 做什么 |
|---|---|---|
| `pa-logs` | 03:00 | 日志切分 + 删 365 天前 |
| `pa-artifacts` | 03:10 | 删 90 天没动过的交付物副本（沙箱原件不动） |
| `pa-sandbox-idle` | 03:20 | 闲置 7 天 → `sandbox stop`（只停不删） |
| `pa-sandbox-orphan` | 03:30 | 用户已不存在 + 3 天 → `sandbox delete` |

预演（不实际执行）：`python -m src.infra.Maintenance sandbox-idle --dry-run`

### 10.3 备份

```bash
mysqldump -uagent -p --single-transaction open_agent_harness > backup_$(date +%F).sql
# 沙箱里的用户文件在 docker volume 里，如需保留请一并备份
```

## 11. 上生产前的安全清单

- [ ] `[app] test_login_enabled` 改成 **false**（否则输入任意用户名就能进）
- [ ] `PA_APP_SECRET_KEY` 是随机值，且**不进 git**
- [ ] 设了 `PA_APP_LOGIN_PASSWORD`，或已接公司 SSO
- [ ] `.env` 权限 600，属主是运行服务的账号
- [ ] 数据库账号只授权本库，不用 root
- [ ] 放 Nginx/网关上做网络准入——平台 RBAC 管的是**工具权限**，不是准入
- [ ] `openshell_enabled=true` 时检查 `config/sandbox-policy.yaml` 的出站白名单
